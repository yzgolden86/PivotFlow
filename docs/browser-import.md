# 浏览器辅助与账号导入

“导入账号”把已登录上游页面或 All API Hub 的账号认证资料带入 PivotFlow。流程是选择文件、检查来源、选择目标、生成固定差异预览，再确认保存。一次处理一条账号资料，新账号默认停用并关闭自动维护。

从“账号管理”或“站点管理”点击“导入账号”，选择“All API Hub 文件”或“浏览器页面助手”。原 `#/browser-import` 路由与账号修复链接继续可用。账号“更新凭证”窗口可直接定位当前账号；维护任务明确返回 `browser_required` 或 `expired` 时，只有对应账号的已确认失败结果提供恢复入口。

## 获取来源资料

在导入页展开“从浏览器取得资料”，填写期望来源 origin 和站点平台，再下载页面助手或复制书签脚本。期望来源只含协议、主机和可选端口，例如 `https://source.example`；它与完整 API 基础地址分开核对。

在已登录上游的顶层页面运行助手。先核对来源、API 基础地址、平台和账号标签，再点击“读取当前页资料”。助手仅检查 `user`、`auth_token`、`access_token` 和 `token` 等明确支持的本地存储键；Sub2API 访问令牌模式额外读取 `refresh_token` 和 `expires_at`。存储受限或内容超限会明确显示，助手不会扩大扫描范围。

发现多个不同凭证时，需要明确选择一份；也可以手工填写。Cookie 必须手工填写，并提供平台要求的用户 ID。助手不读取页面 Cookie、不访问剪贴板，也不向网关或上游发送请求。来源不符或在 iframe 中运行时，助手在读取存储前拒绝执行。

点击“导出 JSON 文件”下载到本机，表单中的认证资料随即清空；关闭助手会清理表单、临时下载 URL 并恢复先前焦点。之后回到 PivotFlow，选择刚下载的文件。

导出的 JSON 和 All API Hub 明文备份包含认证资料，按账号凭证文件保存和处理。页面助手与恢复链接本身只携带来源、平台或安全编号，不携带认证资料。

## 支持的文件

| 格式 | 接受范围 |
| --- | --- |
| PivotFlow 轻量桥接 | `format: "pivotflow-browser-bridge"`、`version: "1.0"`，`entries` 中的来源、完整地址、站点名称、平台、账号标签、凭证类型与 `credential` |
| All API Hub | 明文 `2.0`、`3.0`、`4.0` 账号备份；`accounts.accounts` 或 `accounts` 数组中的已知账号认证字段 |

轻量凭证为 `api_key`、`access_token`、`cookie` 三选一，可带 `user_id`；Sub2API 访问令牌可带 `refresh_token`、`expires_at`。当前支持 New API / One API 家族、AnyRouter、Veloera、Sub2API 和 OpenAI Compatible；后者只接受 API Key，Sub2API 不接受 Cookie。

All API Hub 的认证类型接受 `access_token` 和 `cookie`；访问令牌来自 `account_info.access_token`，Cookie 来自 `cookieAuth.sessionCookie`，Sub2API 的刷新资料来自 `sub2apiAuth`。加密备份、未知版本或不支持的单项类型需要重新导出或使用现有账号表单。

文件最多 2 MiB、1–64 条账号、单份凭证 16 KiB、名称 191 个 Unicode 字符、URL 2048 字符。文件原始 UTF-8 和 JSON Unicode 转义必须有效，未配对的 surrogate 转义会明确拒绝；合法字符对及原本的 U+FFFD 字符可以保留。JSON 深度、重复键和编码后的请求另受校验。修改所选条目的已知凭证字段后，需要重新检查；其他条目和被忽略的备份部分保留在本次页面内存。

外部余额、健康、模型、签到、设置和请求头不会被当作新事实导入。浏览器保留原始 JSON 文本交给服务器，避免先解析再序列化掩盖重复键。原文件及其秘密只存在于当前页面内存和本次请求体，离开页面后需要重新选择文件才能重新生成预览。

## 来源和目标匹配

点击“服务器检查”只读取当前本地配置，不写账号，也不请求上游。来源与 API 基础地址必须属于同一个 origin。基础地址按完整前缀匹配，非默认端口和合法转义路径保留；`/%61pi` 与 `/api` 等 unreserved 字符的编码会归一，`%2F` 仍保持编码，不能与实际路径分隔符混淆。路径大小写和不同 API 前缀仍分别匹配；不接受用户信息、查询、片段、点路径或私有网络地址。

页面每页展示 10 条来源，标识重复、缺凭证和不支持的项目，并给出同完整地址下的账号候选及匹配原因。账号标签和文件用户 ID 都只是提示，不能独自证明实际身份。需要修复既有账号时，明确选择目标；从账号链接带入的初始目标若与文件完整地址不符，会清除并提示重新核对。

凭证类型、主凭证、刷新令牌及实际有效期都相同时可以生成“无变化”预览，保留名字、开关和历史。即使主凭证相同，提供了不同的 Refresh Token 或有效期也需要明确选择目标、验证并生成更新预览。验证后会按实际冻结资料再次判断；文件中的用户 ID 提示不构成变更证据。既有账号尚未记录稳定用户 ID、验证首次取得真实 ID 时，也需要明确选择该账号后重新生成预览。验证取得的稳定用户 ID 与既有账号不同会拒绝更新；相同身份已存在而未指定目标时，要求明确选择，避免重复创建。无法取得稳定用户 ID 时，预览会说明身份范围。

省略或设为 JSON `null` 的刷新字段保留既有值；主凭证相同时，省略的有效期也保留既有值，换主凭证后则使用新资料或其 JWT 有效期。错误类型的刷新字段或有效期会拒绝。直接文件明确提供空刷新令牌可以在验证后清除；页面编辑留空会省略该字段。已删除站点的名称可以复用，旧版本留下的软删除记录不会复活；活动站点同名异地址仍会阻止创建。

## 验证与停用保存

先勾选“我已核对来源、完整 API 地址与目标账号”，再选择一种方式：

| 方式 | 本次行为 |
| --- | --- |
| 验证并生成预览 | 有界只读验证，最多 90 秒；读取实际账号信息或 API Key 的模型列表，显示范围、时间和可确认身份 |
| 停用保存预览 | 不请求上游；允许创建停用账号，关闭自动任务。与既有凭证的实际资料完全相同时可以返回无变化；刷新令牌或有效期修正也必须先验证，不能未经验证更新既有账号 |

浏览器导入验证共用同站点执行门控与 HTTP 请求预算，既有账号还使用有界验证租约。验证不会自动刷新长期令牌、揭示路由 Key、签到或创建渠道。刷新令牌仅作为导入或需保留的既有配置冻结，后续维护按现有账号规则处理。

`browser_required` 表示上游需要浏览器操作；打开同来源页面处理后，由用户明确重新验证。`expired` 表示认证已失效，需要重新取得资料。停止验证会取消当前只读等待，迟到响应不会覆盖新选择，也不代表人工签到或其他上游操作已经成功。

## 确认应用与下一步

预览只显示来源、目标、字段变化、保留字段和验证范围，响应不会回传认证资料或私有配置指纹。确认应用只提交预览编号，服务器在本地配置事务中重查相关指纹，并写入已经冻结的凭证。相关配置变化后，旧预览失效，必须重新检查。

新站点只在确认应用时创建；默认启用站点管理、使用系统代理、时区 Asia/Shanghai。新账号始终停用、自动签到和刷新关闭。修复既有账号仅替换凭证并把当前状态设为“未知”，保留标签、开关、余额、签到历史、模型、渠道和绑定；确定失败整项回滚，重复应用返回同一结果。

应用成功后可“查看账号”“核对渠道同步”或进入“接入配置”。渠道入口只按实际应用结果的账号编号预选；停用账号会提示先到账号页核对启用。生成上游渠道差异仍需用户主动点击，并遵守[现有同步预览](config-import.md)的固定快照、手动接管和缺失 Key 规则。

## 恢复待确认结果

服务端预览在当前实例内保留最多 10 分钟，共享容量为 16 条、64 MiB。恢复 URL 只含安全 `preview_id`、`account_id`、`site_id`，可选 `helper=1`；重新进入页面只 GET 原预览，不自动应用。

应用响应丢失时，页面立即读取同一个预览编号。读到“已应用”就显示实际结果；读到“正在应用”继续核对；“结果待确认”会冻结文件、凭证和目标输入，同一完整来源地址也不能用新预览替代。

“结果待确认”需要先到账号页核对实际配置，再勾选“我已在账号页核对实际导入结果”，才能移除同一预览。移除只解除当前实例的等待记录，不再次应用或撤回已提交内容。预览到期或进程重启后没有持久恢复保证，重新导入前仍应核对实际账号。

## 管理接口与验证边界

| 方法与路径 | 用途 |
| --- | --- |
| `POST /admin/browser-import/inspect` | 请求体 `document` 为原始 JSON 文本字符串或对象；返回安全检查结果 |
| `POST /admin/browser-import/preview` | 文档、条目索引、目标账号、名称、模式和来源确认；生成固定预览 |
| `GET /admin/config-previews/:id` | 读取同一预览与结果 |
| `POST /admin/config-previews/:id/apply` | 确认应用固定快照 |
| `DELETE /admin/config-previews/:id?acknowledged=true` | 浏览器导入的 unknown 结果经人工核对后移除；普通 ready 预览无需此参数，applying 仍拒绝 |

本阶段使用合成 Provider、真实 SQLite 事务、实际构建的控制台和独立合成浏览器页面验收，没有运行生产网关或请求真实上游。真实站点的登录策略、HttpOnly Cookie、Sub2API 浏览器 origin 私钥证明、MySQL/PostgreSQL 和多实例共享租约仍需相应环境确认。实现及本地整合证据见[阶段验证记录](superpowers/plans/2026-11-23-browser-import-bridge-verification.md)。
