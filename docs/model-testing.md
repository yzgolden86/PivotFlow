# 模型测试

## 两种测试

### 站点账号直测

从账号可用模型中选择模型，测试请求直接使用该账号的站点凭证。它用于验证“这个账号和上游模型是否可用”，不会证明所有投影渠道都健康。

### 渠道测试

从渠道配置的模型中选择模型，测试经过 PivotFlow 的 URL、Key、协议模式和故障边界。它用于验证“下游请求经过路由后是否可用”，会记录实际模型、协议、Key 索引、首字节时间和响应摘要。

## 推荐测试顺序

1. 刷新账号余额。
2. 同步账号模型。
3. 站点账号直测一个最小文本请求。
4. 同步站点渠道。
5. 渠道测试同一个模型，再测试一个跨协议模型。

`models_required` 表示账号尚未同步模型；`credential_expired` 或 `credential_rejected` 表示凭证请求被上游拒绝，不代表余额接口一定能覆盖模型调用权限。

## 测试内容

系统设置里的默认测试内容只是测试请求的默认文本，不是模型能力基线，也不会替代模型测试页面。个人使用通常只需要短文本；流式测试和跨协议测试应按需开启。

## 关于模型能力基线

模型能力基线已从个人高频主流程中移出。它不能可靠回答“某个渠道今天是否适合你的工作”，还会增加测试成本和解释负担。需要保留实验记录时，优先使用渠道测试结果、请求日志和实际响应。
