# 核心概念

## 站点

站点是一个上游服务的连接记录，包含名称、基础 URL、平台类型、时区、代理和探测状态。站点本身不等于一个可调用的路由 Key，也不承载某个用户的余额。

## 账号

账号是站点下的一组凭证。凭证可以是访问令牌、模型 API Key、Cookie 或用户名密码。账号控制面使用它来刷新余额、列出模型、获取公告和执行签到。凭证字段不会由管理 API 明文返回。

“访问令牌”是上游管理接口的会话/系统令牌；“API Key”是用于模型请求或路由投影的模型密钥。两者用途不同，不能因为权限高就互换。

## 渠道

渠道是代理真正选择的路由候选，保存一个或多个 URL、一个或多个 Key、模型映射、优先级、协议模式、限流、成本倍率和冷却状态。手工渠道适合特殊上游或需要多个 URL 的高级场景。

## 访问令牌

访问令牌由 PivotFlow 发放给 Claude Code、Codex、Gemini、OpenAI SDK 等客户端。它可以限制允许模型、允许渠道、成本上限和并发。它不是上游站点令牌，也不能用于站点签到。

## 为什么要分开

站点控制面需要“能管理账号”的凭证，路由数据面需要“能调用模型”的 URL 和 Key。把两者混成一个表单会导致签到、余额和路由权限相互污染。PivotFlow 的“同步站点渠道”是两者之间的明确投影边界。

## 同步的所有权

同步创建的渠道拥有 URL、模型、投影 Key 和来源绑定等字段。你可以在渠道页调整优先级、倍率、限流和启用状态。下一次同步只更新投影拥有的字段，不会无条件覆盖所有手工设置。出现冲突时，界面会显示绑定状态和最后同步错误。
