# 配置导入与渠道同步

JSON 备份导入、WebDAV 恢复和渠道页的“同步站点渠道”都会先读取并计算差异，不会在点击预览时修改业务配置。确认应用时，服务器使用预览时固定下来的导入文档或上游发现结果，而不是重新读取当前文件或再次下载。

差异会分别统计“新建、更新、无变化、保留、冲突、停用”。预览只显示对象、字段名和结果摘要，不显示凭证、API Key、请求规则、代理地址或设置值。可按动作筛选，也可搜索对象、字段或说明。

## 文件版本与范围

当前可迁移 JSON 的版本是 `1.0`，`type` 只有三个值：

| `type` | 内容 |
| --- | --- |
| `all` | 连接配置和系统设置 |
| `connections` | 站点、账号、账号模型清单、渠道、绑定和下游令牌 |
| `settings` | 可迁移系统设置、通知和 WebDAV 备份设置 |

这是配置合并格式，不是数据库导出。计费历史、支付或充值回执、待结算日志、结算回执、请求日志、统计和余额历史不会随 JSON 恢复。需要准确运行状态时使用[备份与恢复](backup-recovery.md)中的整库流程。

## 使用范围与生命周期

预览记录保存在当前服务进程内，不写入数据库，也不会替代数据库备份。固定快照可能包含敏感凭证，只保留在进程内存中，预览 API 只返回字段名和结果摘要。服务重启后，旧预览不可再读取，需要重新生成。

同一实例最多保留 16 个预览，保留内容编码后的合计预算为 64 MiB；Go 对象和请求临时副本另有开销。达到任一上限时，新的预览会提示容量已满；旧预览过期或删除后才会释放位置。单个本地 JSON 文件或 WebDAV 文件最大 32 MiB。

普通预览从生成时起有效 10 分钟。应用进入终态后，结果会再保留约 10 分钟，便于应用响应丢失时通过读取预览恢复结论。实际应用还会重新检查本地配置是否仍与生成预览时一致；发生过相关修改时，预览显示“已失效”，必须重新生成。

只有同时满足以下条件才能点击“确认应用”：

- 预览状态为“待确认”。
- 没有冲突条目。
- 预览尚未过期。
- 服务器仍允许应用该预览。

“正在应用”“已应用”“失败”“已失效”和“结果待确认”都会禁用“确认应用”。已应用的预览再次读取或再次请求时只返回既有终态，不会再次写入。

## 浏览器账号资料

[浏览器导入](browser-import.md)共用固定配置预览，但接收的是轻量账号文件或 All API Hub 账号子集。检查只读、验证有界，原文件中的余额、签到和模型事实被忽略。新账号停用保存，既有不同凭证必须验证并明确目标；应用只写冻结的账号认证资料，保留现有历史和渠道。

成功结果可定位实际账号和“同步站点渠道”窗口。渠道链接只预选目标，不自动请求上游或生成渠道；停用账号需先核对启用。浏览器导入的 unknown 预览需要人工核对并通过 `acknowledged=true` 才能移除，同一来源的应用中或未知记录会阻止替代预览。

## 差异动作与状态

| 动作 | 含义 |
| --- | --- |
| 新建 | 目标实例中没有匹配对象，确认后创建 |
| 更新 | 匹配到现有对象，确认后修改列出的字段 |
| 无变化 | 匹配成功，导入内容与当前值一致 |
| 保留 | 使用当前本地值；例如手动管理渠道、未知设置或无法恢复的历史令牌 |
| 冲突 | 身份、引用、认证类型或配置内容存在歧义，整份备份或当前账号的预览不能应用 |
| 停用 | 上游 Key 已确认移除或账号已停用，确认后停用关联渠道；历史数据保留 |

| 状态 | 页面含义 |
| --- | --- |
| 待确认 | 差异已生成，可以检查并确认应用 |
| 正在应用 | 服务器正处理该预览；不要重复提交 |
| 已应用 | 固定快照已提交；重复读取会得到同一结果，不会再次写入 |
| 失败 | 本次应用已明确失败；按安全错误位置检查后重新生成预览 |
| 已失效 | 生成本地预览后配置发生变化，或上游发现结果已经过期；重新生成后再确认 |
| 结果待确认 | 无法确认事务是否已提交；先读取状态并人工核对，不要盲目重试 |

## 从 JSON 文件导入

1. 打开“系统设置”中的“导入导出”，在“从文件导入”处选择 PivotFlow 导出的 JSON 文件，或把文件拖入选择区。
2. 点击“预览导入”。浏览器会解析文件并交给服务器；服务器校验版本和备份范围后，冻结这份 JSON 并生成差异。
3. 检查计数、字段变化、保留字段和冲突说明。需要更换文件时点击“重新选择文件”，旧预览会被丢弃。
4. 点击“确认应用”。此时浏览器只提交预览 ID，服务器应用已冻结的同一份文档。

本地文件在选择并进入预览后会从页面的待导入文件中清除。之后修改磁盘上的原文件不会改变已生成的预览；要使用新文件，必须重新选择并预览。

备份中的对象 ID 只用于在同一份导入文档内建立引用，不会直接当作目标实例的主键使用。匹配规则如下：

- 站点按规范化基础 URL 匹配。主机名不区分大小写，路径末尾斜杠归一化；同名但地址不同的站点按冲突处理。
- 账号按映射后的站点和账号标签匹配。
- 渠道按名称匹配。同名渠道的认证类型发生变化时按冲突处理。
- 下游令牌按令牌摘要匹配，不会把历史令牌摘要直接复制成目标实例的可用令牌。
- 重复身份、缺少站点/账号/渠道引用、无效条目、凭证不可解开和不支持的凭证类型都会在写入前列为冲突。

全部配置和连接备份在一个配置事务中应用。确定的条目写入失败会回滚整份备份，不留下部分站点、账号、渠道、绑定或令牌更新。提交阶段无法确认的结果会显示“结果待确认”，需要按下文流程核对。系统设置备份也使用同一流程。

### 站点渠道绑定

连接配置可以包含可选的绑定清单，但只携带 `site_account_id`、`channel_id`、`projection_key` 和 `pricing_group`。它不包含站点任务、同步时间、错误或运行历史。

- 文档内的站点账号和渠道 ID 按本次导入映射到目标 ID，不直接作为目标主键。
- 恢复的绑定保存为人工接管状态，避免后续站点同步覆盖导入内容。
- 账号、所属站点或渠道在目标中不可用时，绑定保持停用；绑定恢复本身不会启用父对象或启动同步。
- 目标中未出现在清单里的绑定会保留，不会被导入过程删除。
- 旧版 JSON 没有绑定清单时，沿用原有的人工接管规则；已知停用渠道的绑定保持停用，不能猜测投影键或渠道对应关系。

同一账号下重复的绑定标识、同一渠道对应多个绑定、无效账号或渠道引用，以及目标渠道已被另一绑定占用，都列为冲突并阻止整份应用。`projection_key` 是不透明身份，恢复不自动去掉前后空格；标识最长 191 个字符，定价分组最长 64 个字符，均不接受 NUL、回车或换行。预览只给安全条目位置和字段名，不展示绑定标识的具体值。

### 账号模型清单

账号模型清单按每个导出账号整份替换，包括空清单。恢复会保留目标中同模型已有的观察时间，同时精确恢复备份的 `disabled`、`stale`、路由类型和来源。同一账号下同一模型出现重复条目时，无论路由类型是否不同都按冲突处理。

恢复不使用日常模型发现的合并或清旧语义。两者分开执行：恢复清单不会启动模型发现，后续日常发现也仍按自己的规则更新账号模型。

## 从 WebDAV 恢复

1. 先在“WebDAV 备份”中保存并启用有效的 WebDAV 地址和凭证。
2. 点击“预览恢复”。服务器从配置的地址下载一次备份文件，并按下载到的内容生成固定预览。
3. 检查差异后点击“确认应用”。确认过程不会重新下载文件，因此即使远端文件随后改变，应用内容仍以刚才的预览为准。
4. 要读取远端最新文件，点击“重新生成预览”或再次“预览恢复”，然后重新核对差异。

WebDAV 返回网页而不是 JSON、认证失败、文件超过 32 MiB 或备份格式无效时，预览不会生成。请检查文件地址是否指向实际备份文件，并确认 WebDAV 账号有读取权限。

WebDAV 上传通过同一目标的缓存绕过回读、完整长度和 SHA-256 判断内容是否已验证。恢复预览仍会下载一次并冻结下载内容；它不把旧的 `last_sync_at` 当作内容凭证，也不会因预览而重新上传。校验状态和安全边界见[备份与恢复](backup-recovery.md)。

## 检查并同步站点渠道

在“渠道管理”点击“同步站点渠道”，选择一个或多个启用中的站点账号，再点击“生成差异预览”。单次最多选择 16 个账号，控制台每批最多同时等待 3 个账号的预览任务。

每个账号会读取上游各把模型 Key 的模型、协议和分组，并生成独立的渠道差异。结果逐账号显示，可在同一窗口逐项点击“确认应用”；一个账号成功不会自动应用其他账号。

“取消生成”会停止当前窗口的等待，并向已创建的站点任务发送取消请求。页面离开或关闭时不会把尚未确认的预览当作已应用。任务已排队、已开始或响应中断时，保留显示的站点任务 ID，按站点维护任务的“重新观察”语义核对，不要仅凭页面提示重复操作。

站点同步沿用站点的账号租约、任务队列和请求预算。多个账号的部分成功、失败和取消分别报告，不用一个账号的结果推断另一个账号。

应用一个账号的预览时，服务器在单个配置事务内重新检查该账号及其已绑定渠道是否变化。确定的写入失败会回滚该账号的全部渠道写入；其他账号不受影响。提交结果无法确认时显示“结果待确认”。任何渠道冲突都会阻止该账号应用。

### 手动接管渠道

手动接管渠道在预览中显示为“保留”，字段说明为“手动管理的渠道保持不变”。确认同步不会覆盖它的名称、URL、模型或 Key，也不会因为上游 Key 移除而停用它。

如果希望恢复上游更新，先在渠道列表对该渠道点击“恢复自动同步”，把所有权交回站点投影，再重新生成并确认差异预览。仅重新打开同步窗口不会自动恢复手动渠道。

### 上游 Key 的新增、缺失与发现失败

- 上游新增可发现的 Key：预览显示新建或更新；确认后创建或刷新对应自动管理渠道。
- 上游完整发现成功且某个已有 Key 已消失：自动管理渠道显示“停用”，确认后停用渠道并保留请求历史和统计，不删除历史数据。
- 上游发现只完成一部分：无法确认的现有渠道显示“保留”，上游未返回的 Key 不会被推断为删除。
- 手动管理渠道：无论上游 Key 是否存在，都保持原状。

## 备份恢复范围

控制台 JSON 备份恢复的是 `1.0` 可迁移配置，包括站点、账号、账号模型清单、渠道与上游 Key、下游令牌、可选绑定、通知、系统设置和 WebDAV 设置，具体以所选范围为 `all`、`connections` 或 `settings` 为准。

恢复不会带回以下运行历史：

- 请求日志、请求身份与尝试历史。
- 公告缓存和已读状态。
- 运行指标、渠道请求统计和其他统计。
- 余额每日快照、签到历史、账号本地观察值。
- 已有下游令牌的累计费用、用量统计和最后使用时间。
- 计费历史、支付或充值回执、待结算记录与结算回执。

导入已有账号时会保留当前余额观察、签到历史和用量统计；导入已有渠道时会保留请求历史和统计；导入已有令牌时会保留费用与用量计数。备份 JSON 本身也不包含计费日志或结算回执，不能替代[安全与备份](security.md)中描述的数据库、计费文件和主密钥备份。

同一上游 Key 的最新健康与冷却观测也会保留，不用备份中的旧观测覆盖它；上游密钥发生轮换时，新密钥从无历史观测开始，保留备注、人工停用和模型范围等配置。

无法解密或恢复的历史令牌会显示“保留”，不会删除现有记录，也不会生成一个猜测的明文令牌。旧备份中的令牌条目没有协议限制字段时，若目标实例已存在同一令牌，会保留当前协议限制，避免恢复后意外扩大权限。首次创建的令牌没有旧限制可继承，应用前请核对备份中的令牌权限。

未知设置和由容器管理的设置会保留当前值，不会被备份覆盖。备份中修改现有自动投影渠道时，确认应用后该渠道转为“手动接管”，防止后续站点同步撤销恢复内容。

## 应用结果、缓存警告与重启

应用成功后页面显示“已应用”。备份预览会汇总站点、账号、渠道、绑定、令牌和设置的处理数量；站点渠道预览按账号显示结果。已经应用的预览重复请求会返回同一终态，不会重复写入。

如果主数据库事务已提交，但混合存储的 SQLite 缓存副本同步失败，页面显示“配置已提交，但缓存副本同步失败，请核对副本状态”。这是提交成功后的警告，不应把整份配置当作回滚后再次应用。检查副本状态和连接后，再按运行健康页面确认恢复情况。

混合存储的配置写入与副本发布在当前服务实例内串行处理。多个服务实例共用主数据库时，各实例的 SQLite 副本可能暂时不同；本阶段不提供跨实例即时一致保证，不能用另一实例的旧列表判断本次配置是否回滚。

访问令牌权限重载从主数据库读取，避免把副本中的旧权限重新加载。若读取或重载仍失败，结果会明确提示“访问令牌权限重载失败”，当前内存权限可能尚未生效；应核对主库与服务状态，通过重新加载令牌或正常重启恢复，再验证权限，不能重复导入来猜测结果。副本同步和令牌重载同时失败时，两项警告会一起显示。

备份包含需要重启的系统设置时，应用成功后会请求当前进程优雅重启。站点渠道同步不因普通渠道更新触发重启。

## 过期、结果待确认与重试

预览过期或服务器重启后，读取会提示预览不存在或已过期。重新生成并再次核对，不能复用旧页面状态直接提交。

如果确认应用的 HTTP 响应在传输中丢失、超时或浏览器断网，页面会重新读取预览：

- 读到“已应用”：说明服务器已确认提交，不需要再次应用。
- 读到“正在应用”：继续等待并重新读取，不要重复提交。
- 读到“待确认”且服务器仍允许应用：页面会提示再次人工核对；只有在你重新确认后才可提交。
- 读到“已失效”或“失败”：根据位置检查后重新生成预览。
- 读到“结果待确认”：停止自动重试，人工核对当前配置和相关请求记录。

“结果待确认”与普通的网络传输失败不同。它表示数据库提交或事务结果无法确认，服务器和页面都不会猜测“失败”。此时不要重复点击应用，也不要从旧文件再创建一份相同预览后立即提交；先通过预览 ID 重新读取，并检查当前配置、请求历史以及适用的上游实际状态。

## 管理 API 契约

控制台使用以下接口：

| 方法与路径 | 请求 | 用途 |
| --- | --- | --- |
| `POST /admin/backup/preview` | `data` 为备份文档 | 冻结 JSON 导入并生成差异 |
| `POST /admin/backup/webdav/preview` | 空对象 | 下载 WebDAV 文件并生成差异 |
| `POST /admin/site-accounts/:id/sync-preview` | 空对象 | 登记站点发现任务，返回 `task_id` 和是否合并的 `merged` |
| `POST /admin/browser-import/inspect` | `document` 为原始账号 JSON | 只读来源和目标检查 |
| `POST /admin/browser-import/preview` | 文档、单项索引、目标、模式和来源确认 | 冻结浏览器账号预览 |
| `GET /admin/config-previews/:id` | 无 | 读取预览、应用进度或终态结果 |
| `POST /admin/config-previews/:id/apply` | 空对象 | 应用固定快照 |
| `DELETE /admin/config-previews/:id` | 无；浏览器 unknown 需 `?acknowledged=true` | 丢弃预览记录；正在应用时拒绝删除，未知结果需先核对 |

站点同步任务成功时，任务的 `result_ref` 为 `config_preview:<预览 ID>`；随后用该 ID 读取共享预览并调用同一个应用接口。活动任务、取消、合并和未知结果的处理继续使用原站点任务接口。

旧的无预览入口 `POST /admin/backup/import` 和 `POST /admin/backup/webdav/import` 返回 HTTP 428 与 `preview_required`，不再直接写入配置。客户端应先调用对应预览接口，检查差异后再应用预览 ID。

管理 API 的错误只给出稳定错误码和允许公开的条目位置，不返回原始 SQL、Provider 响应正文、凭证、请求头、完整代理地址或设置值。预览 ID 是不透明值，应按 URL 组件编码；不要把它当成长期任务 ID 或配置对象的稳定标识。
