## UI 学习的明确取舍

1. 密集日志适合比较首字、费用与缓存；长错误和原始 JSON 应进入详情，避免单条异常把整表撑高。一次请求的尝试序列比独立多行日志更容易排障。
2. 能力矩阵和分步表单适合复杂配置，但只读事实、人工声明、探测结果和当前冷却必须区分，不能靠一个绿色开关表示所有能力。
3. All API Hub 的就地加载、失败重试、选择器恢复与非打断反馈比新增装饰更值得学。测试运行中关闭弹窗、切换页面或重新打开，应有明确生命周期。
4. Octopus 的侧 Dock / 底 Dock 有视觉连续性；PivotFlow 的功能更多，移动高频入口应精选并带标签，而非把十多个图标全部放进底栏。
5. 先维护统一价格与数据口径，再加分享 PNG、排名和更多图表。未知值、零价、估算和确认账单必须有不同呈现。

ccLoad 公开图中的版本是 4.10.33-beta.1，不是 5.0；Octopus 分组图仍显示当前源码已移除的模式。截图只用于布局观察，当前功能以固定提交源码为准。PivotFlow 文档图为合成数据；正式 UI 审阅见 [本项目 UI 报告](pivotflow-ui-audit.md)。
