审阅日期：2026-11-19。基线：`90aee957`，v0.4.9，2026-10-24。范围是正式前端源码、入口、文档与 `docs/assets` 合成截图；没有启动服务或读取真实数据。“已有”表示当前源码存在相应机制，浏览器体验未实测。

| 站点 | 签到中心 `#/checkins` | CheckinsPage | 账号与历史视图、手动/批量签到 |
| 站点 | 公告中心 `#/announcements` | AnnouncementsPage | 未读筛选、详情、站点聚合 |
| 路由 | 渠道分发 `#/channels` | ChannelsPage | 同步渠道、手工渠道、Key/URL/模型、路由诊断、Key 健康 |
| 路由 | 令牌管理 `#/tokens` | TokensPage | 模型/渠道/费用/并发限制、启停、复制令牌 |

## 3. 首次使用：已有能力与跨页连续性

| 阶段 | 已有能力 | 完成任务仍缺的连接 |
| --- | --- | --- |
| 登录 | 独立管理员登录、密码显隐、SPA 再校验 admin 角色 | 启动网络错误只有连接失败提示，缺重试和受限诊断入口 |
| 添加站点/账号 | 默认同时添加首个账号；Provider、时区、代理和自动任务可配置 | 提交后没有明确引导到凭证验证；同时创建账号的按钮仍称保存站点 |
| 验证凭证 | 用户、余额、模型数、路由 Key；加密保存、留空保留和 API Key 能力说明 | 验证成功后没有直接继续适用的签到、同步渠道、模型直测或令牌创建 |
| 签到/公告 | 账号/历史、未读/详情、批量任务 | 空态缺少上下文动作，例如添加账号、刷新模型或处理浏览器验证 |
| 同步渠道 | 账号搜索、选搜索结果、进度、逐项成功/部分/失败；账号批量同步也有反馈 | 完成后缺测试渠道和创建令牌的下一步；需要自己换导航找到 |
| 创建访问令牌 | 模型、渠道、费用、并发、到期与启停 | 成功弹窗只复制 Key；缺当前公网地址、四类客户端配置及首个请求入口 |
| 首次请求 | 账号直测和渠道测试，耗时/首字/用量/费用/协议链路 | 直测不等于验证下游令牌与真实代理；需要串起令牌、地址、模型、日志 |
| 诊断 | 历史错误摘要、活动 JSON 调试、只读路由诊断、Key 健康 | 已有入口分散，缺从一次失败直接带范围跳转和持久请求/attempt 关联 |
| 备份恢复 | JSON、WebDAV、上传/恢复、大小验证和凭证提示 | 缺导入前差异/计数预览，主密钥与数据库配套关系应在恢复入口说明 |

证据：[站点页](../../../console/src/pages/SitesPage.tsx)、[账号页](../../../console/src/pages/AccountsPageV2.tsx)、[渠道页](../../../console/src/pages/ChannelsPage.tsx)、[令牌页](../../../console/src/pages/TokensPage.tsx)、[模型测试](../../../console/src/pages/ModelTestPage.tsx)。

总体上，单页内操作已有较完整的反馈，主要改进点是跨页“接下来做什么”。现有 Key 详情、活动调试、日志错误摘要和同步进度应继续复用。

## 4. 空态、批量、错误与费用

| 主题 | 成熟部分 | 剩余缺口 |
| --- | --- | --- |
| 空态 | 普遍有 loading/error/empty；站点/账号有添加入口 | 渠道、令牌、签到与模型的空态多为纯文案；空库与筛选无结果应给不同下一步 |
| 批量范围 | 站点/账号/渠道可批量；路由同步有进度、部分成功、跳过原因 | “全选本页”和“全选”文案混用；筛选/翻页后作用域容易误读 |
| 错误解释 | `siteErrorMessage` 对 WAF、凭证锁、超时、限流、无模型、缺 Key 和 WebDAV HTML 转为中文 | 未知错误仍可显示原串，启动和全局搜索加载失败的恢复入口不充分 |
| Key 状态 | 未检测与正常分开，状态分类细；单 Key 和批量检测已有，批量有费用提示、20 项限制、停止后续 | “检测/复检或清理”术语不一致；状态与请求的真实排除原因仍需连接 |
| 费用显示 | 标准/有效费用、站点价目/本地来源、历史倍率范围已显示 | “上游实扣”现有标签容易超出后端事实；当前是站点价目与用量推导，应称站点价目估算，实际账单确认另列 |
| 页面加载 | PageErrorBoundary 隔离单页崩溃，加载操作有禁用和状态 | StatsPage 的 Promise.all 同时取主统计、选项与概览，辅助请求失败可能拖垮主数据 |
| 全局搜索 | 页面/站点/账号/渠道/模型，Ctrl/Cmd+K | 缺上下键/Enter、资源失败状态及关闭后的显式焦点恢复 |

证据：[共享状态与错误说明](../../../console/src/pages/shared.tsx)、[站点共享组件](../../../console/src/pages/siteShared.tsx)、[数据面板](../../../console/src/pages/StatsPage.tsx)、[日志](../../../console/src/pages/LogsPage.tsx)、[搜索](../../../console/src/components/GlobalSearch.tsx)。

费用与数据语义还应将“客户端最终成功率”和“上游尝试成功率”分开。前者回答用户请求是否成功，后者解释上游质量；当前活动 ID 跨尝试复用，但只保留当前快照、完成即移除。后端事实与具体缺口见 [项目现状](pivotflow-current-state.md)。

## 5. 视觉系统、主题、壁纸与性能

- [styles.css](../../../console/src/styles.css) 有字体、圆角、表面、文字、强调色和明暗令牌；三级文字和强调色注释记录了对比度调整。颜色达标仍需结合背景/主题实测，不能据注释宣称完整 WCAG 合规。
- [theme.ts](../../../console/src/theme.ts) 有多套预设、字体、圆角、侧栏/内容宽度和动效。默认布局应确保重要字段清楚，外观自定义不能承担错误解释。
- 记录列表仍有大量 10–12px 次要字。本轮未做 200% 缩放、长模型名、高 DPI 或屏幕阅读器验收。
- 壁纸接受 http(s)，cover/contain/tile、压暗与随机源；玻璃默认关闭，透明表面才启用。长列表采用接近视口尺寸的模糊层，避免每行独立 blur。
- 源码中软件光栅 p90 33.3ms → 16.7ms 是历史测量，本轮没有复测，不应当作今天设备上的结果。
- 系统 prefers-reduced-motion 和用户减少动效均有实现。后续统一弹窗或列表虚拟化仍应守住这些能力。

已有外观投入相当丰富，新增 UI 优先围绕接入、诊断、范围与恢复；不宜再次大规模改配色、玻璃和壁纸。

## 6. 窄屏、键盘与弹层

| 项目 | 已有机制 | 可确认的缺口 |
| --- | --- | --- |
| 响应布局 | 620/760/880px 断点，移动侧栏遮罩 | <=620px 隐藏部分渠道 URL/路由/模型/限额，令牌只留名称等少数列，站点隐藏地址和摘要；需要详情兜底 |
| 移动侧栏 | skip link、焦点陷阱、Escape、关闭后恢复焦点 | 这套行为没有统一应用到各类弹窗 |
| 通用 Modal | portal 到 body、Escape、dialog/aria-modal | 缺初始焦点、完整 trap、关闭恢复、统一滚动锁；`aria-label` 有名称，仍可统一到标题关联 |
| 全局搜索 | 自动聚焦、Escape、点击结果 | 缺上下键、Enter、失败反馈和焦点恢复 |
| 浮层 | AnchoredPopover/Portal 避免层叠和裁剪 | 需保持所有页面复用，测长文字、窗口边缘和嵌套模态 |

证据：[App](../../../console/src/App.tsx)、[Modal](../../../console/src/pages/siteShared.tsx)、[ChannelKeysModal](../../../console/src/pages/ChannelKeysModal.tsx)、[AnchoredPopover](../../../console/src/components/AnchoredPopover.tsx)、[GlobalSearch](../../../console/src/components/GlobalSearch.tsx)。源码已经明确显示 Modal 的行为缺口；实际键盘/触屏体验尚需浏览器回归。

## 8. 建议改进与验收

| 顺序 | 用户任务 | 目标 | 可观察的验收 |
| --- | --- | --- | --- |
| 1 | 从空库开始 | 首装清单，沿现有来源/账号/渠道/令牌/请求路径 | 当前进度和下一动作清楚，可跳过与恢复，跨页保留上下文 |
| 2 | 凭证验证后继续 | 成功区提供适用的签到、同步、直测或令牌动作 | 不用回侧栏找下一页；纯 Key/不支持签到/缺调用 Key 有明确说明 |
| 3 | 令牌到真实客户端 | 当前公开地址、Claude Code/Codex/OpenAI/Gemini 精确配置及首个代理请求 | 只含下游令牌；复制可用；失败关联同一请求解释 |
| 4 | 理解费用 | 一套来源、估算、倍率与缓存说明 | 同名概念同公式；站点价目不冒充账单确认，费用值可跳同范围日志 |
| 5 | 辅助加载失败 | 分离统计、筛选和概览的错误态 | 辅助失败主数据仍显示、可局部重试；旧响应不覆盖新范围 |
| 6 | 批量范围 | 当前页/筛选集数量，保留/覆盖/级联预览 | 文案与实际集合一致，关闭后结果可找，只重试失败项 |
| 7 | Key 状态 | 检测术语一致，诊断原因与已有详情关联 | 保留当前单 Key/批量，不重复造入口 |
| 8 | 恢复前预检 | 文件类型、版本、计数、覆盖与重启影响 | 无效文件拒绝；合法差异可预览；加密凭据与主密钥关系清楚 |
| 9 | 键盘操作 | Modal/搜索统一焦点、trap、方向键/Enter/恢复 | 打开、遍历、执行/关闭可纯键盘完成，不逃到遮罩后的页面 |
| 10 | 窄屏信息 | 隐藏字段可由展开行或详情查看 | 375/620px 能访问 URL、路由、限额、费用与时间，入口有文本/可聚焦 |
| 11 | 当前文档图 | 复用正式合成截图脚本 | 导航和页面对应当前代码，标明合成数据，无真实账号/Key |

这个排序是 UI 内部任务顺序，可靠性与计费等总体优先级见 [整体建议](recommendations.md)。将首装和诊断作为完整任务交付，再整理局部操作；截图更新应在相关交互稳定后进行。

## 9. 本轮不需要重新开发的能力

已有活动调试快照、历史错误摘要/复制、Key 详情与健康、单/批量检测、同步 progress 与逐项成功/部分/失败、账号批量路由同步、删除级联提示、侧栏键盘行为和 reduced-motion。本次研究的新增点是入口连续性、持久请求证据、范围预览、费用语义及一致交互。

## 10. 验证限制

没有运行真实登录、上游请求、WebDAV、导入/下载、剪贴板、视觉 E2E 或屏幕阅读器；没有在 375/620px、200% 缩放、高 DPI 与低 GPU 下实测。前端 typecheck 通过、167 项测试通过是本轮主任务的逻辑与源码守卫结果，不等于上述浏览器验收。后续 UI 改动应使用合成数据和真实浏览器补足。
