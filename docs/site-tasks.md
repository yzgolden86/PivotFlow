# 站点维护任务与共享限速

余额、签到、模型与路由同步、公告和价目表读取共用控制面请求预算。它与访问令牌、渠道和代理数据面的 RPM / 并发限制互相独立。

## 控制台操作

账号管理、签到中心、公告中心以及渠道页的“同步站点渠道”在各自操作提示中展示相关的进行中、失败、部分完成和结果待确认状态。提示按操作类型及当前站点范围显示，已成功的任务历史不再平铺为共享进度区。页面切换不会丢失已提交任务；关闭同步窗口只结束窗口交互，任务继续，可回到相关操作页查看提示。

操作完成后保留右上角结果通知；页面内提示最多两行，只显示汇总与最近一项原因。悬停“查看结果”可预览完整原因和逐项结果，点击、触摸或键盘 Enter 可固定浮框；浮框内可用 Tab / Shift+Tab 访问各个恢复按钮，Escape 关闭并返回入口。取消、重新观察、读取活动任务和核实后解除锁定均在此浮框中，收起提示不会改变任务的锁定状态。

- **取消进行中操作**：取消当前提示范围内的进行中操作，停止本地尚未提交项，或调用服务器取消接口中止排队和在途请求。提交响应尚未回来时会先记住取消意图，拿到 ID 后再请求取消。服务器对登记中的任务先发出取消意图，再等待执行器返回实际结果，最多等待 3 秒；等待超时保持未确认并继续观察。已经确认成功的签到不会因后续余额探测被取消而改成失败/取消。取消失败显示“取消未确认”，不能假装已经停止。
- **重新操作**：已确认失败或部分完成的目标可从对应操作入口再次执行。成功结果不会自动重放；进行中和结果待确认的操作会阻止同一账号重复执行。部分成功的同一目标可能再次读取模型和协调渠道，应先核对已完成部分。
- **结果待确认**：提交响应丢失或轮询中断不代表上游操作失败。已有 ID 时“重新观察原任务”沿用原任务；没有 ID 时先“重新读取活动任务”。仍无法恢复时先核实上游结果，再明确选择“核实后解除锁定”。解除锁定仅清除本地观察，之后重新操作有重复执行风险。
- **活动任务观察**：登录后的控制台统一观察当前进程已登记的任务，页面切换不会重新提交任务。页面可见时每 10 秒读取，恢复可见时立即读取；观察出错或有结果待确认项时，可在操作提示中“重新读取活动任务”。重新加载页面后恢复活动任务，已结束记录仍可用原 ID 查询，界面不自动恢复所有历史结果。

签到被余额刷新或模型与路由同步占用时，账号行提供返回账号管理或渠道页的处理入口。凭证过期或需要更新身份信息时，失败提示直接打开对应账号的凭证编辑器；上游需要浏览器验证时提供对应站点入口，处理后仍需核对原操作结果。浏览器导入仅作为账号编辑器中的可选扩展，不作为常规修复路径。

模型与路由同步在每个账号行显示最新任务的进行中、成功、失败或部分成功结果；悬停或点击该结果可查看已更新、已确认、已停用和失败的具体渠道，操作提示的详情也列出有问题的账号与渠道。凭证或账号整体失败且尚未处理渠道时，只显示账号错误，不把未知渠道标为更新成功。

New API Key 清单发现目前最多确认一页、100 个 Key；返回的总数或分页状态表明清单不完整时，同步显示未完全完成并保留原有渠道。异常或缺失的清单不会被视为上游已移除所有 Key。

批量签到遵守当前站点筛选，跳过未启用账号/站点、纯 API Key 和不支持服务端签到的平台。批量余额刷新跳过纯 API Key。每个浏览器会话最多 4 个提交/观察 worker；跨标签页和定时器的限制由服务器负责。

取消不能撤回已经完成的上游签到、凭证轮换和渠道写入。取消中的网络操作也可能已经被上游接收；必要时在上游核实。当天已取消的定时签到（含尚未开始执行的排队项）留下取消记录，不再自动重新入队，手动重试仍由用户决定；次日恢复正常日程。已取消的定时全量刷新在当前进程延至下个原刷新间隔，不会伪造 `LastRefreshAt`；重启后按原持久状态重新判断。需要浏览器操作的挑战不由服务器循环请求来破解。

## 服务器的任务预算

同一个正在排队/执行的账号操作会返回相同 `task_id`，响应含 `merged: true`。终态不是可复用缓存，之后明确发起的新操作会获得新 ID。模型全量同步与单独余额读取不错误合并；自动同步保留手动接管约束，不与强制人工协调混为一谈。

默认最多 128 个已登记维护任务、最多 4 个实际执行任务。同站点任务串行，等站点门期间不占全局执行名额。排队最长 10 分钟，进入执行后另给 2 分钟；超出预算失败，可重新发起。队列满返回 HTTP 429 / `site_task_queue_full`，服务停止返回 HTTP 503 / `server_shutting_down`，两者是明确未准入的可重试失败。

现有账号租约在创建任务记录前获取，排队期间持续续期，结束释放；租约竞争不生成大量无用历史，执行中失去租约明确报告 `site_task_lease_lost`。定时任务和人工任务共享登记、取消和全局名额；自动刷新继续使用原 6 小时加 0–29 分钟错峰。公告每日租约继续保留 26 小时。全站公告批次也逐站协调到同一子任务，父任务的 `progress.items` 记录各站点任务身份和结果；观察失败保持 unknown，全部子项取消则父项取消，不混入确定执行失败。

## 实际 HTTP 请求预算

由站点服务创建的所有 Provider 客户端共享同一预算，覆盖检测、凭证验证/续期、余额、签到、模型、公告和价格请求。按规范化 **origin（协议、主机和端口）** 分组，路径、账号、Key、代理设置不会另开预算；多个站点配置指向同一 origin 也共享。

| 项目 | 默认行为 |
| --- | --- |
| 单 origin 并发 | 1 个在途响应；读完 body 或关闭后释放。取消时关闭响应；传输尚未退出不能提前释放 |
| 请求开始间隔 | 至少 250ms，等待可取消，不占全局 HTTP 槽 |
| 全局真实 HTTP 并发 | 4；独立于后台任务 4 槽 |
| 429 | 记录共享冷却，后续同 origin 调用立即返回 `provider_rate_limited` |
| 503 | 带 `Retry-After` 时也进入共享冷却 |
| 冷却时间 | 有效 `Retry-After` 秒数或 HTTP 日期；无效、缺失、已过期或溢出时为 30 秒 |
| 自动重放 | 不因 429 重放签到 POST；保留现有非限流暂时故障的有界重试 |

预算不持久化，进程重启清空。它是本进程保护，不是多实例共享的全局限流服务；已有 SQL 任务租约仍负责它覆盖的账号/日任务互斥。Webhook 是单独的出站通知，不消耗站点管理预算；实际模型调用继续走数据面限制。

价目表按站点合并同时发生的读取，共享原站点门和 HTTP 预算。每次共享读取最多 8 秒，并纳入服务关停和 WaitGroup；单个页面断开不会取消其他等待者，也不因等待方取消写入负缓存。共享读取自行提交缓存，价格源失效后旧 generation 的结果不能写回或返回，新等待方使用新 generation。保留原价格缓存和本地估算回退，因此排队超时/限流可能导致本次费用使用本地估算，不能称为上游账单确认。

## 管理 API 与诊断

- `GET /admin/site-tasks`：当前进程的活动维护任务，不以启动前残留的历史 running 行伪造活动任务。
- `GET /admin/site-tasks/:id`：保存的任务状态；带 `site_id`、`site_account_id`、`progress` 和可用的 `budget` 快照。queued/running 行失去当前进程登记（例如重启或最终状态写入失败）时投影为 unknown / `observation_interrupted`，不假报仍在执行，也不把未知变成失败重试。
- `POST /admin/site-tasks/:id/cancel`：取消排队/运行任务；终态保留真实状态。

预算快照只包含 `active`、`waiting`、`next_request_at`、`cooldown_until`，不包含站点 URL、凭证、请求头或上游原始响应。任务详情及批次子项的错误字段仅输出允许列表错误码；数据库中原有的原始错误不透传。`waiting` 是真实 HTTP 预算等待，不是数据库任务队列总长。任务历史沿用原保留策略；不自动重放进程退出前的旧任务。当前进程无法确认所有权的活动行不能由取消接口宣称已停止，仍需核实原任务。

模型同步的 `progress.routes` 只记录实际确认的渠道结果，每项包含渠道 `name`、`status` 和可选允许列表错误码 `error`。状态限于 `updated`、`unchanged`、`deactivated`、`failed`；终态更新保留已有渠道结果与进度计数，其他字段不作为管理响应输出。
