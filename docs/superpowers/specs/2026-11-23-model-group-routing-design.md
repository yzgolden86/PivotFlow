# 以模型／组组织路由策略：设计

日期：2026-11-23，Asia/Shanghai。依据[已批准路线图](../../research/2026-11-19/recommendations.md)的 P2 条目继续实施。用户已授权连续本地实现、隔离验证、整合与清理；本阶段的实现选择由执行者负责，不重复请求流程确认。

## 意图与完成条件

个人网关使用者应能从一个客户端模型出发，回答它会经过哪些渠道、为何优先或被跳过、均衡与粘性如何作用、健康与费用会改变什么，以及去哪里查看真实尝试。当前这些信息分散在渠道诊断和系统设置，旧诊断还有独立求值产生的偏差。

交付一个“模型路由”工作台，复用已有统一映射组、渠道、Key、URL 和令牌。当前候选诊断与真实选择共用候选形成规则；历史按真实保存的请求与尝试展示。打开诊断不发出上游请求、不推进渠道／Key／URL 游标、不消耗限额、不清理或写入冷却和粘性。

验收至少包含：统一组的直接模型与别名渠道并集；通配与精确池优先；实际轮询权重；基础／有效优先级；令牌模型、协议及 allow/deny 渠道范围；可用时段、日限额、冷却和全冷却兜底；Key 当前请求名范围与协议 URL；RPM／并发已满；只读诊断前后真实轮询序列一致；诊断与合成代理的实际渠道、模型、协议、失败转移记录相符。

## 方案与范围

1. 独立的路由组配置，覆盖各组策略及成员优先级。更灵活，但需新增持久配置、备份迁移、权限与会话策略，超出当前解释既有调度的验收范围。
2. **执行者选择：模型／统一映射组工作台 + 共用只读候选规则。** 保留当前调度权威配置，先形成能解释并核对真实调用的完整路径。

本阶段沿用全局 `route_strategy` 的 balanced/sticky、健康与 TTFB 设置以及渠道优先级。使用现有映射编辑器与渠道编辑器，工作台提供准确入口。最低价格自动选路、每组策略覆盖、Grant 存储重构、会话身份／WS transcript 改动、缓存和浏览器辅助属于后续独立方案。

禁止把模型清单、进入候选池或估算价标成“实际可调用”“下一次必选”或“已对账”。未知健康样本、读取失败与动态约束需要明确标记。

## 当前源码契约

- `selector.go` 先读当前统一映射的候选并集，精确池不可用时才扫描启用渠道的精确／显式映射／通配支持；旧“fuzzy”命名现已没有子串语义。
- `selector_cooldown.go` 先可用时段，再日费用，再渠道／实际上游模型／所有 Key 冷却，最后排序；全冷却仅挑最早恢复的一条候选。
- `selector_balancer.go` 与 `smooth_weighted_rr.go` 按基础或有效优先级分层；实际权重是启用 Key 总数减当前冷却数，最小为 1。Key 的当前请求模型范围在尝试阶段求值，不能拿范围内 Key 数冒充现有渠道轮询权重。
- 健康是整个渠道的近期上游样本，失败与首字惩罚都按样本置信度折扣；有效优先级可以越过基础优先级层。粘性在排序之后只按基础优先级是否与首位相同决定前移。
- 下游渠道限制在候选排序之后执行；健康参考池和粘性是否前移必须保留这一顺序。令牌模型和协议限制在准入阶段执行。
- Key `AllowsModel` 检查原始请求名，不自动展开映射组；模型冷却则按重定向／映射／body model 规则后的可能实际上游身份判断。
- URL 的声明、转换请求族和 auto 已学习能力决定可尝试协议；没有实时探测不能证明能处理任意请求体、工具或图片。
- 费用以完成后的用量计算，渠道／令牌额度是软限额；有站点绑定并不证明站点价格已缓存可用。诊断不能触发价目刷新。
- 模型统一映射现在为热生效；旧路由文档的重启说明需纠正。全局 balanced/sticky 和健康配置仍使用进程生效快照。

## 后端组织

### 共用候选求值

在选择器边界提取不推进调度状态的候选形成步骤，保留原有查询、降级、过滤和兜底顺序。真实请求在该步骤之后推进 SWRR 并应用粘性；诊断使用相同候选结果，按确定性层级展示，不调用选择器的可变调度方法。

候选快照包含一次求值时间、冷却／费用观察、健康配置与统计、进入候选池的渠道集合、候选来源及兜底标记。运行数据读取失败必须在诊断响应中公开安全警告，不能把缺少数据说成没有冷却。真实代理维持既有降级行为。缓存快照对象保持只读，改变外层顺序或兜底标记时使用私有 slice／Clone。

保留原 `GET /admin/channels/:id/route-diagnostics` 和系统访问只读入口，改为同一模型诊断结果的目标渠道投影；不保留第二套候选判断公式。

### 模型清单

新增管理员只读 `GET /admin/routing/models`：按当前模型名／映射组检索，默认 50 条、最大 100 条，支持 limit/offset 和 search。归并当前启用组，显示对外名称、少量别名预览及完整数量、配置渠道数和启用渠道数。保留没有可用成员的已配置组，清楚显示“没有启用渠道”。通配渠道单列，不把通配能力伪造成已发现的任意模型。

清单仅展示配置覆盖，不做逐模型诊断，不查询价格或发送探测。大量模型不导致每个模型一次数据库／上游查询。search 对当前对外名称、全部当前组成员及实际配置名称组合求值，搜索不只匹配已截断的预览。历史上已移除的别名不属于当前清单。别名预览最多 8 个、诊断组名预览最多 50 个，均有总数与截断说明。

### 模型诊断

新增管理员只读 `GET /admin/routing/diagnostics?model=...&client_protocol=...&token_id=...`。支持四种现有客户端协议对应的常见文本请求族；模型必填、最多 512 字符，拒绝控制字符和重复查询参数；token_id 为正整数，缺省为全局管理员观察。

返回 version 1、生成时间、请求名与当前统一名称、组成员预览、当前进程策略、健康／TTFB 开关、候选池模式、所选令牌的安全准入解释、全部相关渠道的安全状态及摘要。每条渠道同时包含：

- 候选状态与优先级层；是否此刻存在可尝试 Key／协议 URL；阻断发生在准入、候选形成还是实际尝试。
- 基础与有效优先级、失败／首字惩罚和各自样本量；无样本显示未知，不显示已确认的 100% 成功率。
- 真实渠道轮询权重、模型范围内启用／可用 Key 数，分开命名。份额是同层长期均衡参考，低层是故障转移时的条件份额，粘性时也不是实际命中概率。
- URL 数、声明／自动学习能力和可能的上游模型／协议；只输出索引与安全状态，不输出 URL、代理、Header、凭证或规则内容。
- 当前 RPM、并发、时段、日费用用量／限制与恢复观察。全冷却兜底明确表示允许提前试探，不会把“冷却”与“可正常调用”混淆。
- 费用显示本地渠道倍率及适用 Key 倍率范围、日额度和站点绑定／已有价目观察；不得发起价目读取。说明金额仍未对账，倍率不能跨渠道替代最终费用比较。

相关渠道包括配置里命中请求名／当前组成员的渠道、对应模型条目已停用的渠道、整体停用的渠道，以及通配渠道，即使它们被令牌、能力、冷却或精确池优先排除也展示原因；完全无配置关系的渠道不进入相关集合。响应默认 50、最大 100，有总数和分页；服务端先对完整集合求值，再分页，份额与层级不按页面重算。对模型没有匹配渠道也返回可解释空结果。不存在的令牌返回 404；其它存储错误只输出稳定安全错误，不返回 SQL／凭证。

令牌准入应优先使用当前生效的权限与成本／并发观察；数据库存在但尚未加载或过期停用时明确表示不可验证／不可准入。诊断不读取完整下游令牌。将后台限制变化与正在执行请求的动态变化写成快照边界，不保证下一请求命中。

### 历史连接

工作台提供“查看该请求模型的历史”。完整请求列表新增精确请求模型和客户端协议过滤，范围和令牌保持 URL 可恢复；列表与汇总使用同一过滤。组的当前别名关系不能重写过去的身份，选择组默认按当前对外请求名查看，别名请求通过选择该名字查看。

现有 `RequestTrace.Model` 与 `ClientProtocol` 已随请求摘要保存，无需新增数据库字段或回填。历史层会将模型身份截到 191 字符；精确历史筛选仅支持 191 字符，工作台对更长名称显示边界并提供普通历史入口，不截断后伪装成精确匹配。旧记录没有完整请求身份时沿用既有缺失说明，不推测或重建。

诊断中的历史上游占比保留既有日志来源，但改为明确“已保存的上游尝试”，排除无渠道的最终汇总行，并标记精确请求名／协议和本机今日窗口。历史读取失败独立警告，当前候选诊断仍可查看。记录缺失和过去组变化不得补推测值。

## 控制台任务与视觉

在路由导航新增“模型路由” `/routing`，仍保留渠道分发和模型测试入口。桌面是左侧模型清单／右侧策略说明与候选层；手机是顺序阅读，两侧均有检索／页码，有界 DOM。沿用现有主题、字体、Lucide、焦点浮层、Pagination 和状态组件。

```text
模型路由                         刷新当前快照 · 路由设置
查找模型／别名 [________]         OpenAI [v]  令牌范围 [v]
统一模型组／独立模型              glm-5.3  · 别名 2  · 快照时间
  glm-5.3                       优先级 → 健康评分 → 均衡／粘性 → 真实尝试
  claude-opus-5                 第一层  渠道 A  权重 3  当前可尝试
  ...                          第一层  渠道 B  权重 1  RPM 已满，尝试时跳过
  上一页 / 第 N 页 / 下一页        第二层  渠道 C  条件均衡份额，失败才到这里
                                排除项  渠道 D  令牌不允许 / 模型冷却
                                费用说明 · 查看真实历史 · 编辑渠道
```

刷新、切换模型／协议／令牌的异步结果用 generation+abort 隔离；旧响应不能覆盖新范围。读取失败保留选项和恢复入口，旧快照标为过时并注明原范围，不能混在新模型标题下。令牌列表单独错误／重试，缺失令牌不能自动退回全局观察扩大范围。URL 只含模型、协议和对象 ID。

通过既有设置入口编辑映射与策略。直接链接到设置时选择对应分组；工作台不重复一套设置保存表单。候选编辑链接定位确切渠道，测试入口不自动运行；查看诊断不会调用 POST、秘密 reveal 或探测接口。

清单 API 增加严格 `enabled_only=true|false` 视图，启用名称与通配／空组分开；筛选在分页前完成。令牌编辑保留已有旧别名权限。公开列表整次读取冻结同一映射快照并用于权限过滤。

成功完整上游同步及渠道 replace 刷新确认移除的成员，仅在所有剩余配置渠道（含停用与手动配置）都不再引用其精确名称时从保存的映射中清理；canonical 和未被观察的手填名称保留。失败、局部、含义不明确的空发现不据此删除。条件持久更新避免覆盖并发设置编辑，清理后热刷新注册表。读取清单与诊断不能触发此写入。空组保留在管理工作台，公开模型端点只从启用的实际渠道生成名称。

兼容边界：已启用且未过期旧令牌的白名单仍引用别名时，保留该别名的统一组关系，避免模型清理改变原有的 canonical 访问权限；自动同步不改写令牌。该保留别名不会单独加入当前启用统一清单。管理员可先把白名单改成统一名称，再手动移除旧别名。停用或过期令牌重新启用前需核对白名单。
