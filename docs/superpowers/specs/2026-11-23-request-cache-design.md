# 可选请求缓存与策略优化

日期：2026-11-23。阶段：研究路线最后一项 P2。授权：用户要求先完成剩余工作；沿用隔离实施、合成本地验收、本地整合及归属清理，不提交、不发布、不部署。

## 目的与范围

在反复发送相同的确定性文本请求时，可显式复用一份短期成功响应，降低延迟和重复上游费用。网关响应缓存与上游 prompt cache、配置缓存、会话/连接复用分别计量。缓存默认关闭，只存当前进程内存，不写响应内容到数据库、文件或观测接口。

首期支持 `POST /v1/chat/completions`（OpenAI）和 `POST /v1/messages`（Anthropic），非流式、显式 `temperature=0`、单候选、只有字符串/文本块的完整消息。允许键有递归白名单；工具/函数、媒体、思考块、未知字段、会话身份、Responses、WebSocket、查询参数和编码请求体均绕过。配置了自定义请求规则、协议转换、OAuth 或 AnyRouter 兼容正文改写的实际尝试也绕过，以免隐式加入工具或状态。纯模型名称重定向沿用渠道/映射指纹与失效规则；固定认证/协议头继续由原链路生成。其他代理能力继续按现有语义执行。

## 请求策略

`request_cache_enabled=false` 为默认；客户端通过 `X-PivotFlow-Cache: use` 显式选择复用，`refresh` 强制重新请求并用安全成功响应替换同一键，`bypass` 不读不写。缺失或非法模式均绕过。请求 `Cache-Control: no-store` 不读不写；`no-cache`/`Pragma: no-cache` 在已选择 use/refresh 时强制刷新。上游 no-store/no-cache、Vary:*、Set-Cookie、非 JSON、工具响应、不完整终态、错误、非 200、取消及写入失败均不存。

精确键覆盖令牌 ID/hash、客户端协议、路径、原始正文和影响请求的头；用长度分帧的 SHA-256，保留原始正文差异，不尝试跨别名/格式/令牌合并。认证、缓存控制和传输头不进入语义头集合；其他头全部参与。Cookie／Cookie2 属于会话身份，整个请求绕过。缓存只保留最终下游 JSON 和 Content-Type，不重放上游请求 ID、Cookie、限额、日期等瞬态头。缓存响应的 completion/message ID 与内容原样复用；客户端每次获得新的 `X-PivotFlow-Request-Id`，并获得固定值的 `X-PivotFlow-Cache` 状态。

## 准入、路由与失效

HTTP 认证/令牌并发、全局并发、持久计费准入、模型/协议权限、令牌费用预检均仍先执行。缓存查找使用现有只读候选形成，再检查缓存来源渠道仍在允许候选中及配置指纹相同；不消耗 SWRR 游标、粘性选择、渠道 RPM、上游并发、Key/URL 选择或冷却清除。没有合法候选时沿用原代理错误。

缓存代际在请求形成候选前获取。渠道/Key 修改、统一映射重载、令牌权限重载与手动清空都会清空缓存并推进代际。旧代际的在途响应不能重新填入；查找同样重查代际。每个活跃精确键还保留填充代际：refresh 开始即推进该键代际，较早的普通 miss/refresh 不得覆盖较新的刷新结果。该表仅持有当前请求引用，结束后释放，并设 4096 个活跃键硬上限，超限请求继续正常代理。渠道配置指纹进一步捕获自然配置快照刷新，只含配置字段，排除冷却、创建／更新时间和 Key 数等运行观察；配置启用状态仍需满足准入。开始与完成之间的授权变更按现有在途请求边界处理，完成后不允许旧身份填充。

## 容量与并发

设置保存后按项目现有流程重启生效：开关、TTL（默认 60 秒，5–3600）、条目数（256，1–4096）、正文容量（32 MiB，1–128 MiB）、单条响应（1 MiB，4 KiB–1 MiB）。单条上限不超过总容量下限，因此任意合法单项/重置/批量组合都满足容量关系，无需增加跨设置写入锁。启动读取也校验同一规则；非法持久值拒绝启动。LRU 与 TTL 并用；刷新期间已有条目从 refresh 开始即移除，失败不继续复用旧结果。

所有缓存状态由互斥锁保护；读出提供独立数据，写入提供不可变数据。缓存正文总量与在途捕获正文总量各自受总容量约束，捕获失败只影响是否存储，不改变已有转发。超限、取消、清空竞态都释放捕获资源。指标明确是正文容量与条目数而非 Go 堆内存；原始请求体、正常代理缓冲和下游写出瞬态资源仍受既有全局并发控制。

独立设计检查确认了成功路径的冷却/API Key 缓存刷新会误触语义失效的风险；实现将该内部操作保留在存储冷却缓存层，配置修改才推进响应缓存代际。捕获只在完整代理成功后发布。权限回调在新权限发布后、撤销 Web 会话前执行，撤销失败也不能保留旧缓存。两条映射重载入口都推进代际。

## 结算与历史

本地命中只有在完整写出成功后才记一次令牌成功调用，复用既有幂等 TokenSettlement，tokens/cost 均为零。不得调用上游成功处理器或添加伪造渠道日志，以免污染健康度、URL 延迟与费用。取消/写失败不记成功结算。请求摘要新增固定允许列表的 `cache_status` / `cache_reason`；SQLite/MySQL/PostgreSQL 与副本路径保持一致，旧记录默认为空。不保存请求正文、缓存键、凭证或来源请求 ID。命中请求保留零尝试，客户端最终成功率与上游尝试成功率自然分开。

## 管理与界面

管理员 `GET /admin/request-cache` 返回 version 1 的当前进程策略、观察时间及有界计数；`DELETE /admin/request-cache` 清空并推进代际，进程累计计数保留。读取不探测数据库、不清理缓存、不执行维护。运行健康返回同一只读缓存观察。设置增加“请求缓存”分组，显示默认关闭、支持范围、启用说明、当前策略/容量/命中/绕过与失效原因，并提供清空操作与失败恢复。请求历史显示缓存状态/原因及零新增上游费用语义。

## 验收

使用真实代理 + httptest 合成上游与独立 SQLite 结算库检查重复请求、隔离、权限变更、映射/渠道变更、TTL/LRU/预算、refresh/bypass、工具/会话/媒体/未知字段、错误/不完整 JSON、取消、写失败、清空竞态与并发释放。证明命中不会调用上游或消耗路由游标；费用和健康统计不重复。前端纯函数测试固定 DTO/原因解析，浏览器对真实构建进行合成接口拦截，覆盖设置、清空/失败/迟到/卸载、历史及响应式可达。运行适当定向测试、全后端、双 TypeScript、前端测试、Vite、lint 和 embed；独立阶段审查，随后 Main 复验、不可变归档与安全清理。

## 取舍

选择精确短期响应复用，暂不引入语义相似缓存、跨实例共享、流式合成、请求合并、模型组自动策略或最低价路由。扩展协议必须先证明终态、工具副作用和会话身份语义。当前缓存只是本地优化，实际网关版本与真实部署仍由既有发布流程控制。
