# 控制面任务合并与站点请求预算

2026-11-21。继续用户已授权的路线；实现选择由维护代理承担，不重复请求阶段许可。

## 目标与现状

现有任务表、取消 API、账号租约、站点串行门和自动错峰继续使用。当前手动重复请求会生成独立任务，定时任务不能通过取消 API 中止；价格请求绕过站点门，多账号和多个操作也没有共同的 HTTP 频率/429 预算。账号同步有逐项结果，余额、签到和公告尚缺统一的取消及失败重试。

验收：同站点多账号不会无限并发；重叠的同类工作返回同一任务 ID；排队和执行可取消；逐项状态可见，成功项不会因“仅重试失败”再次执行。

## 方案与边界

选择扩展现有任务和 Provider transport。仅前端禁用按钮不能覆盖多标签页和定时器；新建独立任务系统则重复持久化及租约。保持个人部署和现有数据库结构，不改数据面路由限流，不新增依赖。

- 后台任务按操作、站点、账号和模型刷新语义合并；合并仅限正在排队/运行的任务，不复用历史成功。全局最多 4 个执行任务、最多 128 个合并登记项；超出返回可重试错误。租约先于持久化，未取得租约不写无意义历史。排队最长 10 分钟，执行最长 2 分钟，均可取消。
- Provider ClientFactory 在站点服务构造时共享 RequestBudget；以规范化 origin 为键，不含账号/凭证/路径，重复站点指向同一 origin 也共享。单 origin 最多一个在途 HTTP 响应（读完/关闭 body 后释放），请求开始至少相隔 250ms；最多 4 个真实请求同时运行。使用者等待可取消，等频率时不占全局传输槽。
- HTTP 429（及带 Retry-After 的 503）记录 origin 冷却；有效秒数/HTTP 日期按上游截止时间，缺失/无效/过去的时间使用 30 秒。冷却中的新请求立即返回 provider_rate_limited，不自动重放产生副作用的请求。429 不能变成账号凭证过期。任务查询可返回不含 URL/凭证的共享预算快照。
- 价格请求按站点合并，受同站点门及 HTTP 预算约束；共享读取绑定服务生命周期且最多 8 秒，等待方取消不取消其他等待方。保持现有价格缓存及本地估算回退。
- 定时任务进入同一登记及取消生命周期，保留每日公告租约、签到日语义与原错峰。手动余额与定时完整模型刷新语义不同，不错误合并；相同签到共享执行，先提交者决定 trigger。
- 页面复用统一的任务执行器及紧凑进度区；余额/模型、签到和公告均显示逐项排队/运行/成功/部分成功/失败/取消，可取消单项/整批。仅重试失败和部分成功，不重新执行成功或已取消项。关闭/离开页面只停止本地观察，不把已发出的上游操作宣称撤回；取消发送真实 API。网络观察失败显示“观察中断”，不能当作已知上游失败盲目重试。
- 取消只停止后续工作和在途 context，已经发生的上游签到、凭证或渠道更新不回滚。进程重启不自动重放旧任务；沿用现有历史保留机制。

## 验证

使用合成 Provider/httptest 和 Go 虚拟时间验证共享并发、最小间隔、取消释放、429/Retry-After、不同源站隔离、合并与结束后重建、调度/手动重叠、关停和租约竞争。前端 node:test 验证控制器行为；浏览器以合成账号验证各页、逐项取消、仅重试失败、窄屏与键盘。执行完整 internal 测试、lint、前端类型/测试/构建与最终 Go 编译。无真实上游、真实账号、生产数据或生产服务操作；无 CGO race 和外部 MySQL/Postgres 的验证声明。
