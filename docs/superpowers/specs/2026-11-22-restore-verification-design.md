# 恢复验证与升级说明

日期：2026-11-22。落实研究路线中的 P1「恢复验证与升级说明」。用户已批准按路线持续推进，本阶段沿用隔离实现、验证后本地整合的方式；不提交、推送、发布或部署。

## 意图与现状

个人网关的备份需要有可核对的恢复结果，升级也需要知道程序、存储和主密钥各自的边界。现有 JSON/WebDAV 导入已经具备固定预览、引用映射、整份事务、结果待确认和权限热重载，本阶段复用这些契约。

当前 WebDAV PUT 收到 2xx 就更新 `last_sync_at`，没有回读确认；旧记录不能作为内容校验凭据。现有凭证往返测试使用内存数据库，尚未一起验证目标 ID 冲突、绑定、全部令牌限制及关闭后重新打开的持久结果。部署说明只有更新原则，缺少可执行的恢复验收和回退流程。

## 方案

考虑了三种范围：只补文档与恢复测试可以明确边界，但不能发现上传成功后的内容丢失；在产品内增加恢复演练服务需要额外处理临时库、密钥、任务和清理权限；复用导入流程，增加上传回读校验、独立数据库回归和运维说明，能完成当前验收。第三种为本阶段的工程选择。

参考 All API Hub 的写后验证经验，采用有界回读和明确证据；本阶段保持当前单文件 PUT 的兼容路径。远端版本历史、临时文件 MOVE 提交和多设备合并属于另行设计的功能。回读校验只能证明本次目标内容与发送内容一致，恢复回归则验证可迁移配置的行为，不能混称完整数据库灾难恢复。

## 上传与校验证据

- 导出为既有 `1.0` JSON 格式，范围保持 `all`、`connections`、`settings`；编码后最大 32 MiB，超过时在 PUT 前拒绝。
- 对固定的编码内容、目标 URL 和认证信息执行一次 PUT。成功后 GET 同一目标，禁止缓存，比较完整字节数及 SHA-256。远端内容、认证信息和底层存储错误均不进入错误响应或日志。
- 回读最多 5 次，间隔 1 秒，整个回读阶段最多 10 秒；等待可取消。只对 404、425、423、429、5xx、内容不一致和可重试传输失败进行有界回读；认证拒绝、HTML 和过大响应立即失败。重试只读 GET，不重复 PUT。
- PUT 的 2xx 响应可以含 HTML 状态页；GET 的内容必须是发送的 JSON 字节。失败不会推进上次成功或上次校验时间，也不会删除远端文件。
- 保持进程内单次导出防重入。关闭空闲连接、响应体和计时器，不留下临时服务。
- 增加 `backup_settings` 的五个观察字段：`last_verified_at`、`last_verified_bytes`、`last_verified_sha256`、`last_verified_type`、`last_verified_warning_count`。旧库通过幂等增列获得空证据；旧 `last_sync_at` 保留但显示「旧版上传记录，尚无回读校验」。这些字段不进入可迁移 JSON。
- 成功证据与错误使用配置事务保存。保存前比较开始时的配置，配置变化时仅返回本次旧目标的观察与明确警告，不能覆盖新设置或把旧目标的校验归到新目标。编辑 WebDAV 设置也在配置事务内读改写；目标、用户名或密码变化时清空旧证据。
- 校验完成而状态保存失败或副本同步失败，响应区分「内容已校验」与「状态未保存/副本异常」，不能把后者改成未上传并自动重写。主库已提交但副本失败沿用现有事务警告契约。
- 校验成功响应保持 `status: success`，新增完整 `verification`、`metadata_saved` 和安全警告。主库保存失败/结果待确认时，进程只保留一份与开始配置绑定的加密配置引用及校验摘要，不保留明文 JSON；定时调度先仅重试观察保存，并以该观察时间计算下次备份间隔，不能因时间未落库立刻重复 PUT。设置改变则丢弃旧待保存观察。进程重启会丢失这份内存观察，此时旧记录仍显示未校验，下个正常备份周期生成新的备份；不承诺持久化的备份任务幂等。
- 页面只有证据字段完整且 `last_sync_at == last_verified_at` 才能把最新记录显示为已校验。`last_sync_at` 晚于校验时间（例如旧程序再次上传）显示最新上传尚未校验，较早证据仅作历史；逆序或无效时间同样不能标绿。
- 审查补充：较新的上传或校验时间优先；同一时间的旧版上传或不同字节/摘要无法可靠归属，返回 `backup_status_superseded` 并丢弃较早待保存证据。相同字节/摘要下缺失范围或错误警告数可仅修复元数据；确认已有完整证据不清除后续失败记录。页面与后端均比较完整的时间、大小、摘要、范围和警告数。
- 保存相同明文密码复用原加密封装；旧封装不可读时，明确提供替换密码且当前密钥可用就允许重新加密。恢复预览也允许这种显式修复，没有替换值或当前密钥不可用时保持阻止。
- 自动备份和手动备份调用同一实现；备份中的不可恢复条目以警告数量显示，管理员在 JSON 警告和恢复预览中核对，不把字节校验当作所有凭证均可恢复。

## 独立恢复验收

使用测试自有目录中两套磁盘 SQLite 数据库、不同的合成主密钥；不调用生产启动、调度器或真实上游。源实例通过真实存储导出，目标先生成预览再应用固定文档，关闭后重新打开目标数据库，核对：

1. 站点身份、账号归属和模型清单，目标中无关记录及冲突 ID 不受误用。
2. API Key、Cookie/用户 ID、渠道 OAuth 及通知/WebDAV 凭证在目标密钥下可解密，原密钥不能解开目标密文。
3. 渠道的站点/账号引用与绑定、上游 Key、模型路由和人工所有权遵循已有导入语义。
4. 下游令牌的摘要、可恢复明文、启用/过期、模型、协议、allow/deny 渠道映射、额度和并发限制；恢复后的认证与模型/渠道过滤实际生效。
5. JSON 未承诺的日志、结算回执、已用费用和余额观察不会被当作跨实例历史恢复；已有令牌用量保留，无法恢复的历史令牌有明确警告。
6. 无效引用/认证/规则导致预览冲突，不产生部分写入；重复应用不重复创建。

连接备份增补可选的 `bindings` 引用清单（格式仍为 1.0）：只携带 `site_account_id`、`channel_id`、`projection_key`、`pricing_group`，不携带任务、同步时间、错误或历史。引用按目标 ID 重映射，恢复的绑定以「手动接管」保存并在预览中说明；账号或渠道不可用时绑定保持停用。未列出的目标绑定不删除，旧文件没有清单时保持原有人工接管契约，不能猜测投影键或自动启动同步。

历史存储允许同一渠道关联多个绑定。旧文件恢复停用渠道时，按渠道将全部已有绑定设为手动/停用，保留其身份与同步历史；使用独立的批量存储操作，不能逐条套用新可迁移绑定的占用冲突规则。

账号模型清单按导出账号逐一替换，包括空清单；同账号同模型的重复条目无论路由类型如何均视为冲突。使用独立的 `RestoreSiteAccountModels(ctx,accountID,models)` 存储接口精确恢复 `disabled/stale` 配置并保留目标已有模型的观察时间，不能改变日常模型发现的 `Replace/MergeSiteAccountModels` 保留人工停用语义。

导出在主库的单个配置事务中只读生成快照，避免副本陈旧或并发配置变化产生互不匹配的引用。遗留软删除站点名称的复用更新沿用已有创建操作的原子释放语义，不能因旧 UNIQUE(name) 约束在应用阶段留下部分更新。

恢复核读还发现：启动复制在主库某个配置表为空时跳过清空副本，会留下旧渠道/令牌行。补充一个独立的存储回归：主库查询成功且表为空时，在同一事务中把副本该表恢复为空；读取失败或写入失败则保留旧副本并报错。使用两套合成 SQLite 模拟主库/副本，不能据此声称真实 MySQL/PostgreSQL 驱动已验证。

如果回归发现实质缺陷，先增加能复现它的失败测试，再做最小修复；不扩展现有合并身份或删除语义。

## 页面与运维说明

沿用现有紧凑卡片、主题变量和图标体系。导出「全部配置」明确区别于数据库备份；WebDAV 区域展示尚未校验、旧上传记录、已回读校验和失败，并可查看范围、大小、SHA-256 与遗漏警告。新错误显示可执行的核对方向，长错误和摘要可换行，320/390px 与深浅主题可读。

新增 `docs/backup-recovery.md`、`docs/upgrade.md`，说明 JSON 合并与数据库快照、SQLite/WAL/主密钥、主库与副本、待结算与回执配对、Docker 绑定目录/命名卷、程序版本选择和渠道迁移的区别。给出本地合成恢复验证命令及部署环境验收表；升级前备份、隔离演练、停服替换、验收和失败回退各有明确观察。迁移保留旧列不等于任意旧程序可读取新密文或新语义，回退应使用同一时点的数据库、密钥、待结算记录和旧程序。

## 约束与验证

- 使用当前源码与全部未提交的已验证阶段作为基线；1050 个普通源码/资源文件已逐项 SHA-256 验证复制，九个保护文件只读散列。
- 无新依赖；Go 1.26.10、sonic 构建标签，沿用 React/TypeScript/Vite、现有 SQL 方言和事务接口。
- 不运行主程序或生产数据，不读取环境/密钥内容；合成临时库与模拟 WebDAV 可用于回归。保留所有双花括号占位符原样。
- Vite 资源构建与 Go root/embed 构建、lint 不并行。
- 必要验证：独立数据库恢复、模拟 WebDAV 成功/失败/取消/状态竞争、旧库幂等迁移、前端反馈单测与双 TS、合成浏览器、相关及完整后端检查、lint/embed 构建、文档链接、整合前后散列与保护文件。
- 真实 MySQL/PostgreSQL、真实 WebDAV 兼容性、客户端长会话、线上升级和逐请求账单仍由部署环境验收；本阶段结果不作这些声明。
