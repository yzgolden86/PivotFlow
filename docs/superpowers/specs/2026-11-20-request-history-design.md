# 请求身份与尝试历史

承接用户已批准的可靠网关路线，实施 P1「请求与尝试关联」。基线包含已验证的 P0 未提交改动；隔离工作树承接全部 922 个源码/文档文件，集成时校验基线，不覆盖并行修改。

## 用户行为与范围

- HTTP 代理调用由网关生成 `pf_req_` + 32 位随机十六进制 ID，以 `X-PivotFlow-Request-Id` 返回。客户端提供或上游返回的同名字段不能替换该身份。
- 每个进入执行器的 Responses WebSocket 回合独立生成身份，不改变会话/线程亲和，不插入协议外事件。鉴权中间件拒绝和 WS 帧归一化前拒绝不在本阶段记录范围。
- 请求摘要记录最终语义结果、状态、总耗时、全局并发槽等待耗时。HTTP 已返回 200 的流中断仍是请求失败；取消独立计数。
- 尝试按实际执行顺序记录：渠道/Key/URL 序号、端点 origin、模型、协议、传输、起始/耗时/首字、状态、是否发起上游、协商/重试原因及冷却决策。协议协商、兼容重试、WS 握手回退均可见，不改变原故障惩罚规则。
- 控制台日志页增加「完整请求」视图；原列表标注「上游日志」。详情展现时间线并可复制脱敏诊断。旧日志不推测补造历史。
- 请求统计分别给出最终成功/失败/取消、上游尝试/成功数。来自保存成功的请求摘要；取消不进入最终成功率分母。探测流量不进入此摘要。

## 数据和边界

采用独立 `request_traces` 摘要表，索引时间、Token、请求 ID；详情 JSON 与摘要同一行原子写入，按普通日志保留期清理。logs 只新增 request_id / attempt_number 两个关联字段，不改变既有健康度、费用及日志聚合语义。三种 SQL 方言与混合模式均支持，混合沿用本地日志先写、远端异步同步。

单请求最多保存 128 条时间线事件，超出明确标记 truncated，计数仍累计全部真实上游尝试。列表不返回详情 JSON。独立有界异步队列，队列丢弃和最终写失败提供运行指标；该观测数据不承诺与 P0 财务 journal 相同的耐久性，不阻塞代理可用性。

详情不保存凭证、哈希、Header、Query、URL path、请求/响应体或任意上游错误文本。错误与重试使用固定原因码，URL 仅保存 origin 和配置序号。请求 ID 不接受调用方输入，避免碰撞/注入。管理接口需要现有认证；Token 身份查询强制所有权过滤并删去渠道、Key、origin、上游模型等内部字段。

## 验收

1. 合成上游 401→其他 Key→成功、模型故障→其他渠道、协议协商、内部兼容重试均有同一请求 ID 与递增尝试；日志与之关联。
2. HTTP/SSE 成功、取消、终止帧缺失与 WS 连续回合保持真实最终结果；请求头不会被上游伪造覆盖。
3. 本地拒绝和等待不伪装为已发上游；时间线截断不扭曲汇总；任何 Key/Query/错误体秘密不进入记录。
4. 重复落库幂等；时间和 Token 过滤、重启后读取、保留期清理、混合同步以及越权 404 可验证。
5. 前端类型检查/现有测试/构建和合成浏览器在桌面、窄屏、键盘下验证。Go 使用 sonic 标签，全量 internal 测试、零 lint、构建。

不更改正式 exe，不访问生产数据库，不发布。实际 WS 客户端/远端 MySQL 与 PostgreSQL 服务的覆盖局限在交付说明中列出。
