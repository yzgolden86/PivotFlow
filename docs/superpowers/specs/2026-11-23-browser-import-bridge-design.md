# 浏览器辅助与轻量导入桥接设计

日期：2026-11-23，Asia/Shanghai。依据已批准的 P2 路线继续原生实施，具体接口和边界由实施者结合现有项目决定；无需重复阶段交接确认。此文记录实施选择，不把尚未实现的能力写成完成。

## 目的与现状

用户希望个人 AI 网关接入方便、调用可靠。浏览器里的登录资料、已有 All API Hub 账号和 PivotFlow 的站点／账号／渠道之间还缺一段连续流程。当前已有 Provider、凭证加密、站点任务预算、配置固定预览和事务应用；浏览器 WAF、人工签到和凭证验证也已有明确分类。

新增「浏览器导入」工作页，把用户发起的资料导出与目标核对、凭证验证、差异确认连接起来。导入复用现有站点和账号，不建立独立凭据库，不把文件中的余额、模型、健康或签到结果当作新的服务端事实。

## 方案选择

1. 完整浏览器扩展：能访问 Cookie 和页面会话，但新增安装、权限、发布与版本维护，不适合本次轻量桥接。
2. 用户运行的页面助手和可迁移文件：助手只在当前顶层页面、明确点击读取后读取有限资料；用户下载文件，再在 PivotFlow 中检查目标。这是本阶段采用的方案。
3. 直接向网关跨站发送资料：需处理跨站授权、接收端和恢复状态，敏感数据更难说明，不采用。

采用既有 Go／Gin、React／TypeScript 和浏览器 DOM API，无新增依赖。源码在隔离工作区完成并核对后整合；保持原程序和真实数据，仅进行合成测试，不提交、推送、发布或部署。

## 输入格式与预算

服务端是规范化和匹配的权威；前端只解析 JSON 和显示服务端返回的安全摘要。`POST /admin/browser-import/inspect` 接受 `{document: ...}`，不发上游请求，不写业务数据，也不返回输入凭证。

控制台的 `document` 是保留原始文件的 JSON 字符串；直接 API 调用也可传对象。整个编码请求和被解码的原始文档各自不得超过 2 MiB，超量会在检查前拒绝。服务端先检查整个 JSON 请求中的重复键，再重新解析字符串文档，避免重复键被浏览器解析消除。

支持两类格式：

- PivotFlow 轻量文件：`format: "pivotflow-browser-bridge"`、`version: "1.0"`、`captured_at` 毫秒时间、`entries` 数组。条目只接收 `source_origin`、`base_url`、`site_name`、`platform`、`account_label`、`credential_type` 和 `credential`。凭证只支持 `api_key`／`access_token`／`cookie`，带可选 `user_id`、`refresh_token`、毫秒 `expires_at`，禁止账号密码登录和任意请求头。
- All API Hub 明文账号备份：明确版本 `2.0`／`3.0`／`4.0`，顶层 `accounts.accounts` 或 `accounts` 数组。读取 `site_name`、`site_url`、`site_type`、`account_info.username/id/access_token`、`authType`、`cookieAuth.sessionCookie` 和 `sub2apiAuth.refreshToken/tokenExpiresAt`。只支持已有 Provider 的 access-token／cookie 账号，不猜测 `authType: none` 的含义，不解密备份。其他备份部分不导入，忽略的部分明确列出。

每份请求编码预算 2 MiB，最多 64 条；单项凭证最大 16 KiB，名称最长 191 Unicode 字符，URL 最长 2048 字符。超大、未知版本、无账号、结构损坏给安全错误码；单项不支持、缺少凭证或无效地址作为不可选条目显示，不阻断其他有效条目。原 UTF-8 和 Unicode 转义须有效，拒绝未配对 surrogate，合法 pair／字面 U+FFFD／字面反斜线 u 保留。JSON 同层重复键不能形成不同的检查／应用解释。

`source_origin` 必须是无路径／userinfo／query／fragment 的 HTTP(S) origin。`base_url` 禁止 userinfo、query、fragment、控制字符和非 HTTP(S) scheme；保留合法 API 前缀并规范化末尾斜杠、主机大小写和默认端口。来源与 API 地址必须同 origin。严格按完整基础地址匹配现有站点，不把相同 origin 下不同前缀合并。新地址遵循现有 Provider 私有地址限制；合成测试通过允许私有地址的测试客户端，不改生产规则。

安全检查结果含格式、忽略部分、逐项索引／来源／目标地址／名称／平台／凭证类型／是否有刷新能力／可用与阻断原因，并给已匹配站点和候选账号 ID、标签、匹配原因。没有明文凭证、摘要哈希、Cookie、Refresh Token 或其他备份设置值。用户修改文件、凭证、条目或目标后必须重新核对。

## 浏览器页面助手

控制台提供下载脚本和复制书签脚本。脚本包含可选的期望 origin 和平台，始终不含管理员令牌、下游令牌、网关地址或实际账号秘密。

助手在顶层页面运行，期望 origin 不符时拒绝读取。界面显示来源 origin、平台、API 基础地址、站点名称、账号标签、凭证类型和受掩码的凭证输入。用户点击「读取当前页资料」后，仅尝试 `user`、`auth_token`、`access_token`、`token`、`refresh_token`、`expires_at` 这些有限 localStorage 键；每个值有长度限制。存在多份候选时显式选择，不从任意对象递归找 token，不枚举整个存储。

`user` 仅提取允许的 `id`、`username`、`access_token`；Sub2API 刷新资料只在用户选择该平台后使用。Cookie 只能由用户手动填写，助手不读 `document.cookie`，不能读取 HttpOnly Cookie、IndexedDB 私钥或浏览器扩展存储。存储不可读、无可用资料或字段不支持时保持可手动填写的表单。

下载前再次校验同 origin 和当前所选凭证，生成轻量 JSON；失败不下载。关闭或下载后清理 DOM 中的秘密并释放 Blob URL。助手无 HTTP 请求、无跨站自动发送、无剪贴板读取、无后台任务、无签到或登录请求；页面 CSP 阻止脚本时可用已有导出文件或手动凭证表单。

## 目标匹配与去重

每个预览只处理一个用户选定条目，避免一次导入含混的多账号结果。请求包含原文件、条目索引、可选 `target_account_id`、模式 `verify`／`save_disabled`、目标名称和明确的 `source_confirmed: true`。服务端重新解析选定条目并核对完整基础地址和平台；不相信前端摘要或传回的检测状态。

- 站点按规范化完整基础地址匹配；unreserved 编码归一，其他字节保持大写 `%XX`，`%2F` 与实际分隔符、路径大小写和不同前缀仍区分。多个匹配、活动站点同名异地址、平台不兼容给冲突；既有站点的开关、代理、时区、名称和其他配置保留。
- 相同站点、相同凭证类型、完全相同主凭证可匹配为已有账号。无变化还须比较 Refresh Token 和 EffectiveExpiresAt；辅助资料变化也只更新明确选中的目标并要求验证，未选目标给 `target_required`。验证完成按实际冻结类型／有效期／真实 profile 身份重新判断；输入 hint 不构成变更证据。
- 正向管理用户 ID 可辅助发现同一身份，但不能凭输入文件的 ID 自动覆盖凭证。存在身份或标签候选时提示选择目标，多个候选不能任取第一个。
- 显式目标必须属于同基础地址／兼容平台的站点；既有可确认用户 ID 与验证得到的 ID 不同则拒绝。无法确认稳定 ID 的 Provider 要明确显示范围有限，并由用户核对具体目标。
- 输入文件内的相同身份／主凭证重复显示重复位置；冲突的重复不自动合并。导入同一文件不同条目时，服务端重新检查当前已应用账号，防止重复创建。

目标名称是用户可修改的本地配置，不能混入凭证输入。预览既有账号时保留 enabled、自动签到／刷新、时区、余额、历史、模型、绑定和渠道；不扩大下游权限，不复活停用对象。

检查接口可在服务端解开同一完整基础地址下的既有账号凭证，用于精确匹配和用户 ID 提示；不解开其他站点，也不把明文或哈希返回浏览器。平台兼容按现有 adapter 的权威 ID 判断，已支持的名称别名归一化到同一 ID；`new-api-family` 与 `openai-compatible` 属于不同平台，不自动替换。All API Hub 的平台映射在三个版本间相同；未知平台单项不可选。

活动站点同名异地址在预览规划时给 `site_name_conflict`，不是等待应用触发数据库约束。当前删除流程物理删除，旧版本软删除墓碑的名称可按现有 CreateSite 规则复用；墓碑仍纳入相关配置指纹，不能复活或绕过并发名称变化。`save_disabled` 对主凭证、Refresh Token 或实际有效期变化给 `unverified_update_forbidden`；实际资料完全相同才可无变化。省略／null 的刷新字段保留旧值，错误类型拒绝；同主凭证省略 expiry 保留旧值，替换主凭证不继承旧 expiry。明确空 refresh 可在验证后清除。新站点只在 apply 创建：enabled=true、use_system_proxy=true、Asia/Shanghai、空 tags；新账号停用并关闭自动任务。

凭证修正通过改写页面内存中所选条目的已知字段并重新 inspect 完成；不增加独立的 preview credential override。All API Hub 的修正只改已知账号认证字段，其余部分仍忽略。修正、条目或目标改变后清空来源确认及旧预览。

## 验证、等待浏览器与应用

`POST /admin/browser-import/preview` 在已确认来源和目标后处理：

- `verify`：在有界总时间内调用现有 Provider 凭证准备与账号／模型只读验证，沿用共享 origin HTTP 预算和认证重定向限制。既有账号验证期间持有现有账号操作租约并与维护任务协调；不在数据库事务中做网络调用。只把服务端成功结果作为验证证据，不接受文件或页面自报的成功。
- `save_disabled`：不发上游请求，仅允许新账号，固定创建为停用，自动任务关闭。状态明确为「未验证，停用保存」，禁止用它更新现有凭证或生成路由。已存在完全相同凭证可以显示无变化。
- WAF／浏览器挑战显示 `browser_required`，expired 与它分开。验证失败、取消、超时或网络结果未知不修改现有账号状态。页面保留当前输入，提供打开同来源站点和显式重新验证；不自动连续重试。

成功后用共享 config-preview 缓存保留冻结内容；`kind: browser_import`，元数据包含来源、目标、模式和验证范围／时间。API 只返回安全摘要。总容量、十分钟有效期、终态保留、服务停止、重复应用、失效检查和结果待确认沿用现有契约。

验证总 deadline 为 90 秒。既有账号使用浏览器验证专属的两分钟租约，并共用同实例现有站点 gate 和执行槽，使其他维护操作在该站点排队。现有不同 kind 的跨实例租约不升级为新的全账号强一致机制。

身份证据只取 Provider 当前 profile 响应中的正整数 ID；输入、JWT hint 或请求头的 UserID 不构成已验证身份。profile 没有 ID 时，安全元数据明确 `identity_known: false`，仅表示本次账号读取成功。`AccountSnapshot` 携带实际响应 ID，其他账号维护调用保持现有行为。

导入验证只使用现有 resolver 的 GET、profile 或模型读取；此阶段单独组织这些只读调用，不直接使用会自动刷新长期令牌／揭示路由密钥的完整凭证准备路径。验证请求移除 Refresh Token，完成后恢复输入或需保留的既有 Refresh Token 到冻结凭证。过期资料通过浏览器重新取得；后续渠道同步由用户显式发起，才进入现有路由密钥流程。

应用通过 `storage.WithConfigurationTransaction` 在权威主库重读匹配和相关配置指纹，再创建站点／账号或更新被选中的账号凭证。确定失败回滚整项，不留下孤立站点；提交未知保留 unknown 且禁止自动重试。敏感凭证通过现有 Cipher 密封；事务中只写已经冻结的凭证，不重新验证或刷新。关闭的站点保持关闭；新站点可管理，但新账号默认停用、自动维护关闭。

验证通过也只说明本次凭证／模型读取，不表示已完成签到、完整模型能力或真实推理。更新凭证后账号运行状态重置为 unknown，保留余额和历史事实；旧模型、绑定和渠道不自动变化。结果返回当前站点／账号 ID、动作和明确的下一步，连接现有账号详情、渠道同步差异预览、客户端接入。

预览 ID 可写入 URL，刷新页面通过 GET 恢复安全元数据与终态；输入原文件和秘密只在当前页面内存，不进入 URL、localStorage、sessionStorage、日志或报错。输入变更时丢弃旧非运行预览；应用中或 commit_unknown 禁止创建相同来源的新应用来规避结果核对。应用响应丢失只重读同一 ID。

## UI 组织

新增 `#/browser-import`，「工具」导航为「浏览器导入」；站点和账号页提供入口，凭证更新窗口与浏览器相关任务提供携带账号 ID 的恢复链接。目标 ID 只作为初始选择，文件与站点不符时不能强行套用。

页面采用现有控制台主题、字体、焦点组件和窄屏规则。顶部简洁说明「来源 → 目标 → 预览」；左侧文件／助手，右侧选定来源与目标，预览使用已有 ConfigPreviewPanel。候选记录分页每页 10 条，文件最多 64 条，选择范围清楚；输入显式标签、按键操作、错误聚焦、窄屏列堆叠，长 URL／名字可折行。无需新增装饰图片或依赖。

页面提供：文件选择／替换、服务器检查、逐项选择、目标账号、掩码凭证修正、来源确认、验证并生成预览、停用保存预览、停止验证等待、重新核对、确认应用、原预览恢复及下一步。停止验证是取消只读请求，不暗示已生成的预览被删除；迟到响应不得污染新选择，迟到创建的预览应释放。

## 验收与边界

1. 用独立合成输入证明两个格式的实际字段和版本，非法来源、重复／歧义、账号身份不符、过量输入、未知部分和敏感数据不回显。
2. 用合成 Provider 和真实 SQLite 事务证明验证不写、WAF／取消不改账号、静默停用模式零上游请求、冻结输入、失效、回滚、重复应用和提交未知。
3. 浏览器直接执行用户将下载的助手脚本，检查有限存储读取、不同 origin／iframe 拒绝、多候选选择、下载 JSON、关闭清理和零网络。
4. 真实控制台合成浏览器检查完整导入／修复、目标不符、来源确认、异步竞态、取消、网络丢失后恢复、跨页候选、账号和渠道链接；320／390／768／1280 宽度及短视口 JPEG、键盘焦点和资源预算。
5. 完整内部 Go、前端测试／双 TypeScript／Vite、lint 和 embed 构建通过；独立源码审查后整合，核对原件与全部保护哈希，再归档清理。

真实浏览器站点、扩展商店、HttpOnly Cookie、Sub2API origin 私钥 proof、真实上游／MySQL／PostgreSQL、跨实例租约和部署均未由合成验证替代。本阶段不声称支持整个 All API Hub 备份、原生订阅平台、后台浏览器或人机验证自动化；剩余 P2 请求缓存另行实施。
