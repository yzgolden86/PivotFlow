# 请求历史实施计划

基于 [设计](../specs/2026-11-20-request-history-design.md)，使用已批准路线直接执行。

1. 存储：新增 RequestTrace/RequestAttempt/filter/stats 模型和 SQLite/MySQL/PostgreSQL schema，查询/幂等写/清理、混合适配；为 logs 增加关联字段。用临时数据库验证过滤、保存、去重、清理与混合同步。
2. 代理：生成身份，HTTP/WS 每回合摘要；在物理转发与兼容回退边界采集尝试；以真实最终状态完成记录，接入活动请求 ID 与普通日志。覆盖失败切换、协商、取消、流中断和敏感信息隔离。
3. 管理：独立有界队列和可观测丢弃指标；只读列表/详情/统计，复用身份范围并做 Token 投影。
4. 控制台：完整请求视图、两种统计口径、详情时间线及复制诊断、旧数据提示；继续支持上游日志与活动请求。
5. 验证/集成：前后端检查和独立审查，合成浏览器验证；更新用户文档和研究进度，以基线散列保护主工作区，整合并清理本阶段工作树/产物。

分工：存储与 UI 写集互不交叉；主执行者负责 internal/app 和集成文档。任何参与者保留 P0 和其他人的改动。全程使用临时测试数据及全局编译缓存。

进度（2026-11-21）：任务 1–5 已完成。全量后端、静态检查、前端测试、构建和合成浏览器检查通过；改动已整合到主工作区，主目录定向回归与散列核对通过，临时工作树、分支和验证程序已清理。下一阶段按原路线推进后台健康 UI。具体命令、审查结论与覆盖边界见 [验证记录](2026-11-20-request-history-verification.md)。
