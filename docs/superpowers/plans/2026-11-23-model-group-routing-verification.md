## 行为回归

直接模型和别名渠道取并集，精确池优先于通配兜底；不把 Key 模型范围当渠道轮询权重。时段、日费用、冷却、健康参考池、令牌渠道过滤、基础／有效优先级及粘性前移沿用真实顺序。诊断插入前后的实际轮询保持 `A,B,A,B`；实际直接渠道 503 后别名渠道 200，与持久请求模型、协议和失败转移历史一致。

已修复缓存中 Key 权限与存储值暂时不一致时的诊断偏差。RPM 只读快照统计当前窗口，不清理过期事件。URL 已学习的不支持哨兵过期后忽略但不删除；诊断不推进游标、占槽、解密／刷新凭证或拉价目。

用户完整 20 个 DeepSeek 名称在新建真实合成令牌及四种公开模型格式中已经归并正确。管理端令牌编辑器曾混入原始和过期站点名称；启用统一清单回归先失败再通过。整次公开列表及白名单使用同一映射快照。

完整非空成功上游同步或渠道 `replace` 后，只删除本次有正面消失证据、且所有配置渠道都不再引用的精确成员；canonical、未曾观察的手填名、其他／手动／停用引用保留。活动且未过期旧令牌的别名白名单关系保留，避免其已有 canonical 权限消失；停用或过期令牌恢复前需核对白名单。管理员可把保留白名单改成统一名称后手动移除别名，自动清理不改写令牌。

设置、拓扑和有效令牌引用从主库读取；条件更新按字节比较，CAS 竞争后重读并合并最新用户新增项。Hybrid 主库已提交而副本失败时，当前进程从主库刷新缓存和 alias registry，并报告安全的非致命清理错误。两套独立 SQLite 库验证此路径；MySQL／PostgreSQL 的字节比较代码未在真实服务上执行。自动站点任务的令牌／渠道观察与设置 CAS 不是跨资源的同一事务，极端并发恢复旧别名权限需核对当前映射；渠道 replace 的拓扑和映射写入现已在同一串行化配置事务中完成。
