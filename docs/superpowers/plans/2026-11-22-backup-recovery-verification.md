## 来源与范围

来源为主目录 `main@90aee95761d8fa21ab3f292b3b2930f8fa24be08` 的完整当前状态，其中包含此前已经验证的未提交改动。隔离工作区为 `.worktrees/restore-verification`，临时分支为 `codex/restore-verification`。1050 个普通文件逐项 SHA-256 复制，九个环境、密钥、数据库与原程序保护文件只比较散列。阶段差异以外置 `baseline-files.json` 和 `final-files.json` 为准，不能用 HEAD 差异代替。

实现增加了以下行为：

- JSON 仍为 `1.0`；显式携带可选渠道绑定，按目标 ID 重映射为手动接管。无效引用、重复绑定身份、共享目标渠道和被其他绑定占用的渠道在预览中阻止整份应用。账号模型按导出账号精确替换，包含空清单；日常发现继续保留其原有语义。
- 导出在主库单个配置事务内读取站点、账号和其他配置。真实 SQLite 双连接并发回归证明原来的逐次读取可能混用不同已提交状态，现已使用一致配置快照。Hybrid 的配置与令牌读取原本就在主库；非空陈旧副本夹具用于加强已有契约的验收。
- WebDAV 编码后最大 32 MiB；一次 PUT 后只重试同一冻结目标的 GET。回读完整字节数与 SHA-256 匹配才生成证据。最多 5 次、间隔 1 秒、回读阶段最多 10 秒，认证拒绝、网页和超大内容立即失败，调用者取消或更早截止时间生效。
- 五个持久校验字段通过旧库幂等增列。上传观察和设置均在配置事务内保存，旧目标结果不覆盖新配置。状态保存失败时只保留加密配置引用和摘要，调度先仅重试元数据；主库已提交而副本失败分别返回成功与安全警告。
- 页面区分未校验、旧版、已校验、最新上传未校验、无效和待保存状态，必要时保留独立的本次回执。范围、大小、时间、摘要、遗漏和失败均可核对；绑定应用计数兼容旧响应。
- 运维文档分别说明 JSON 合并与数据库恢复、主库与副本、WAL、每实例计费日志与结算回执、主密钥版本、容器持久目录、准确版本升级和成组回退。

## 恢复与失败回归

独立恢复使用两套磁盘 SQLite、不同合成主密钥以及预置的目标 ID 冲突。直接构造测试 Server，不调用生产启动路径；目标关闭重开后重新验证配置、引用、API Key/Cookie/用户 ID/OAuth/通知/WebDAV 凭证、下游摘要与权限，并实际执行模型、协议、allow/deny、并发及费用准入检查。目标无关行、已有用量和历史限制保留；无效引用和存储故障不能留下部分配置。

主库查询成功且配置表为空时，副本在同一事务内清空该表；查询、删除或写入失败保留旧副本。模型恢复精确保留导出状态和目标已有观察时间；重复或写入故障整份回滚。软删除站点的旧 UNIQUE 名称在更新事务内原子释放，失败时保留历史。

RED 与 GREEN 原始输出保存在外置证据目录，包括 `restore-initial-red.log`、`restore-binding-red.log`、`restore-boundary-red-model-green.log`、`snapshot-red.log`、`webdav-initial-red.log`、`verification-migration-red.log`、`replica-empty-red.log`、`model-restore-red.log` 及对应通过结果。最后增加的 WebDAV chunked 超限、更早截止时间、主库提交但副本失败和目标切换后的待保存观察属于边界验收；它们初次通过，不虚称经历了失败修复。

## 审查发现与回归修复

一名新鲜上下文审查者按实际未提交基线审查，发现五个需要修正的问题。原始独立报告保留在外置 `independent-review.md`，以下修复由实现者完成，以失败回归和最终完整检查验证；没有追加第二轮独立审查。

| 发现 | 修复与证据 |
| --- | --- |
| 较早校验覆盖较新的上传时间，或未写入却报告保存成功 | 同时保护上传和校验时间；同一时间的旧版上传、不同摘要或大小保守视为已被取代。返回 `backup_status_superseded`，不保留或重试旧待保存证据；已完整保存的证据可直接确认 |
| 相同明文密码因随机封装而清除证据 | 复用可解密且明文相同的封装，HTTP 回归核对持久证据和待保存观察均保留，响应不泄露明文 |
| 旧密码封装不可读时，导入替换密码仍被阻止 | 预览只比较可读的非秘密设置，应用将明确提供的密码重新加密；独立磁盘库重开核对当前密钥和证据清空。没有替换密码或当前密钥不可用仍阻止 |
| 比较遗漏范围、警告数，误删待保存证据或隐藏回执 | 后端和页面比较完整时间、大小、摘要、范围及警告数；相同已验证字节可修复范围/警告元数据，修复或确认保留后续失败记录。浏览器分别复现三类回执被隐藏，再验证其可见 |
| 历史上同一渠道存在多条绑定时，旧文件恢复失败 | 按渠道一次设为人工接管/停用，保留绑定 ID、账号/投影身份、分组和同步历史；新可迁移绑定继续执行占用冲突检查 |

`review-regression-red.log` 实际复现全部五个问题，替换密码用例还确认了预览阶段的提前阻止。`review-regression-green.log` 通过全部六组回归。`review-frontend-red.log` 和 `review-frontend-proof-green.log` 记录新的安全状态反馈失败与通过。`review-browser-receipt-red.json` 是页面已加载后、三种回执可见性断言实际失败的证据；导航超时单独保留为测试环境失败，不作为界面 RED。

## 验证边界

所有数据库、密钥、凭据、客户端响应和 WebDAV 均为测试自有或合成内容。程序验证产物只编译，不执行；未启动原程序、读取保护文件内容、修改生产数据库、连接真实上游或真实 WebDAV。未创建提交、推送、发布或部署。

这些检查证明受测的配置恢复、字节校验和状态处理路径。真实 MySQL/PostgreSQL、真实 WebDAV 服务差异、跨实例灾难恢复、逐请求账单与线上升级仍需目标部署按[备份与恢复](../../backup-recovery.md)及[升级与回退](../../upgrade.md)验收。Windows 本轮未运行 Go race detector，不把合成浏览器或普通并发回归称为 race 检查。
